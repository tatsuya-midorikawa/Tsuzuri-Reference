# リテラル

リテラルは、整数・浮動小数点数・真偽値・文字・文字列・コレクションなどの値をソースコード上に直接記述する構文です。Tsuzuri の数値リテラルは、明示的な型サフィックスまたは使用箇所の期待型（双方向型推論）によってコンパイル時に型とビット表現が確定し、範囲外の値は実行時に折り返さずコンパイルエラーとして検出されます。

本ページでは、Tsuzuri が備えるすべてのリテラル表記、基数・桁区切り・型サフィックスの規則、既定型と範囲検査、および複合リテラルを網羅的に解説します。文字列操作の詳細は[文字列](./strings.md)、式の埋め込みと書式指定は[文字列補間と書式指定](./string-interpolation.md)を参照してください。

## 要点

- **数値の既定型と厳密な範囲検査**: サフィックスがなく文脈からも型が決まらない整数リテラルは `i32`、小数・指数リテラルは `f64` になります（配列添字位置の整数リテラルは `i64`）。型の表現範囲を超えるリテラルは `E1009`（または `E0002`）で拒否されます。
- **基数と桁区切り**: 整数の基数は 10 進、`0x`（16 進）、`0b`（2 進）の 3 種類です。8 進リテラルは存在せず、先行ゼロ付きの `0123` は 10 進数の `123` になります。アンダースコア `_` は数字と数字の間にのみ配置できます。
- **正準の型名サフィックス**: Edition 2027 以降（既定の Edition 2028 を含む）では、`86i8u`・`100i64`・`1.5f32`・`0.1d64` のように型名をそのままサフィックスとして付与します。任意精度整数 `bigint` には `I` サフィックスを使います。
- **2 進浮動小数点と 10 進浮動小数点**: IEEE 754 の 2 進浮動小数点（`f16`〜`f128`）と 10 進浮動小数点（`d32`〜`d128`）の双方を備え、いずれも目的のビット幅へ最近接偶数丸めで 1 回だけ丸められます。
- **文字・文字列・バイト列の明確な型分離**: `'a'`（`char`）と `u8'😀'`（`utf8char`）、`"text"`（`string`）と `u8"text"`（`utf8string`）、および `B` サフィックスによる ASCII バイト（`'A'B`、`"... "B`）とスカラー配列（`u8"..."B`）はリテラル構文の時点で明確に区別されます。

| 符号付き固定幅整数 | `-128i8` (`-128sbyte`), `86i16`, `86i32`, `86i64`, `86i128` | `i8`, `i16`, `i32`, `i64`, `i128` | `sbyte` は `i8` の型別名 |
| 符号なし固定幅整数 | `255i8u` (`255byte` / `255ubyte`), `86i16u`, `86i32u`, `86i64u`, `86i128u` | `i8u`, `i16u`, `i32u`, `i64u`, `i128u` | `byte` / `ubyte` は `i8u` の型別名 |
| 任意精度整数 | `42I`, `0xFF_FFI`, `0b1010I` | `bigint` | 桁数制限のない多倍長整数 |
| サフィックスなし小数・指数 | `1.5`, `1.5e-2`, `1E6` | 期待型、未確定なら `f64` | `f16`〜`f128` / `d32`〜`d128` の文脈に適応 |
| 2 進浮動小数点数 | `1.5f16`, `1.5f32`, `1.5f64`, `1.5f128` | `f16`, `f32`, `f64`, `f128` | IEEE 754 binary16 / 32 / 64 / 128 |
| 10 進浮動小数点数 | `0.1d32`, `0.10d64`, `0.1d128` | `d32`, `d64`, `d128` | IEEE 754 decimal32 / 64 / 128 |
| 論理値 | `true`, `false` | `bool` | 数値との暗黙変換なし |
| Unit 値 | `()` | `unit` | 意味のある値を持たない単一値型 |

| 配列 / 固定長配列 | `[1, 2, 3]` | `[T]` または `[T; N]` | 期待型が `[T; N]` のとき固定長配列 |
| 連結リスト | `[\| 1, 2, 3 \|]`, `[\|\|]` | `[\|T\|]` | 不変のチャンク連結リスト |

## 整数リテラル

### 基数表記（10 進・16 進・2 進と 8 進の非採用）

整数リテラルは以下の 3 種類の基数で記述できます。

- **10 進数**: `0`〜`9` の数字列（例: `0`, `42`, `1_000_000`）
- **16 進数**: 小文字の接頭辞 `0x` に続く `0`〜`9`、`a`〜`f`、`A`〜`F` の数字列（例: `0xFF`, `0xdead_beef`）
- **2 進数**: 小文字の接頭辞 `0b` に続く `0`・`1` の数字列（例: `0b1010_0001`）

接頭辞の大文字表記（`0X`、`0B`）は受理されず `E0001` になります。また、**Tsuzuri に 8 進リテラル（`0o...`）は存在しません**。`0o10` は不正なサフィックスとして `E0001` となり、C 言語などで 8 進数扱いされる先行ゼロ付きの `0123` は **10 進数の `123`** として解釈されます（文字列補間の出力書式 `{value:o}` での 8 進文字列化のみサポートしています）。

### アンダースコア桁区切り

可読性を高めるため、数字と数字の間に単一のアンダースコア `_` を挿入できます（`1_000_000`、`0xFF_AA_00`、`0b1100_0011`）。

以下の位置に置かれた `_` はすべて字句エラー `E0001`（`numeric_separator_misplaced`）になります。

- リテラルの先頭または末尾（`_100`、`100_`）
- 基数接頭辞や小数点・指数記号・型サフィックスの直前・直後（`0x_FF`、`1_.5`、`1._5`、`100_i64`）
- 連続するアンダースコア（`1__000`）

```tsuzuri run=mask%3D255%20bits%3D10%20count%3D1024%20leading_zero%3D123
let mask = 0xFF
let bits = 0b1010
let count = 1_024
let leading_zero = 0123
$"mask={mask} bits={bits} count={count} leading_zero={leading_zero}"
```

### 型サフィックスとエディション規則

整数リテラルの直後には空白を挟まず型サフィックスを付与できます。

- **符号付き固定幅**: `i8`（または `sbyte`）、`i16`、`i32`、`i64`、`i128`
- **符号なし固定幅**: `i8u`（または `byte`、`ubyte`）、`i16u`、`i32u`、`i64u`、`i128u`
- **任意精度整数 (`bigint`)**: 大文字 `I`（`100I`、`0x1_0000_0000_0000_0000I`）

JavaScript の BigInt で使われる `n` サフィックス（`10n`）や、Rust の `u8` / `usize` サフィックス（`10u8`）は存在せず、`E0001` になります。符号なし整数サフィックスは `i8u`〜`i128u`、任意精度整数は `I` を使用します。

> [!NOTE]
> **Edition 2026 の短縮サフィックス**: Edition 2026 のソースに限り、F# 互換の短縮サフィックス（`y`=`i8`, `uy`=`i8u`, `s`=`i16`, `us`=`i16u`, `u`=`i32u`, `l`=`i64`, `ul`=`i64u`, `L`=`i128`, `UL`=`i128u`）が受理されます。Edition 2027 以降では正準形統一のため `E0004` で拒否され、`tsuzuri fix --edition 2027 --from 2026` によって型名サフィックスへ自動変換されます。なお、16 進リテラル `0xFFf` の末尾 `f` は 16 進数字として読まれるため整数 `4095` になります。

### 双方向型推論・既定型 `i32`・範囲検査

サフィックスを持たない整数リテラルは、代入先の型注釈、関数の引数型、配列要素の期待型などの文脈から自動的に型付けされます。整数型だけでなく、`f64` や `d64`、`bigint` が期待される位置でもそのままその型の値になります（ただし、すでに型が確定した `i32` 変数と `i64` 変数の間で暗黙変換が行われることはありません）。周囲に型を決める文脈がない場合は既定で **`i32`** に確定します（配列・文字列の添字位置 `xs[0]` のみ `i64` に確定します）。

```tsuzuri run=default%3D42%20wide%3D3000000000%20ratio%3D2.5%20big%3D9999999999999999999999999999
let default_int = 42
let wide: i64 = 3_000_000_000
let ratio: f64 = 2 + 0.5
let big = 9_999_999_999_999_999_999_999_999_999I
$"default={default_int} wide={wide} ratio={ratio} big={big}"
```

確定した型の範囲に収まらないリテラルは、実行時に折り返すことなくコンパイルエラー `E1009`（`integer_literal_out_of_range`。`u128` の上限すら超える非 `bigint` 整数トークンは構文解析時に `E0002`）になります。たとえば型注釈なしの `3000000000` は既定型 `i32` の上限（`2147483647`）を超えるため `E1009` となり、`3000000000i64` または `: i64` の指定が必要です。

符号付き整数型の最小値（`-128i8`、`-2147483648`、`-9223372036854775808i64` など）も単一の負リテラルとして正確に記述できます。一方、符号なし整数型に対する負のリテラル（`-1i32u` など）は `E1009` で拒否されます。

## 浮動小数点リテラル

小数点 `.` または指数部 `e` / `E` を持つ 10 進数値、あるいは浮動小数点サフィックスを持つ数値は浮動小数点リテラルになります。小数点を使う場合は `0.5` や `1.0` のように**小数点の前後両方に少なくとも 1 桁の数字が必須**です（`.5` や `1.` は小数リテラルになりません）。16 進・2 進リテラルに浮動小数点サフィックスを付けることはできません（`E0001`）。

### 2 進浮動小数点 (`f16`, `f32`, `f64`, `f128`)

IEEE 754 準拠の 2 進浮動小数点型であり、正準サフィックスは `f16`、`f32`、`f64`、`f128` です（Edition 2026 のみ短縮形 `hf`、`f`、`F` を受理）。サフィックスと期待型の双方がない場合は既定で **`f64`** になります。

リテラル文字列はコンパイラ内部の高精度演算（`rustc_apfloat`）によって目的の型の精度へ**最近接偶数丸め（roundTiesToEven）で直接 1 回だけ丸められます**。`f64` を経由することによる二重丸め誤差は生じません。有限値として表現可能な最大値を超えるリテラル（`f64` における `1e309` や、`f16` における `65536.0f16` など）は無限大へ丸められず `E1009`（`float_literal_out_of_range`）になります。

### 10 進浮動小数点 (`d32`, `d64`, `d128`)

金額計算や税率計算など、2 進表現では循環小数となる `0.1` のような 10 進小数を誤差なく扱うための IEEE 754 10 進浮動小数点型です。

| 型 | サフィックス（Edition 2026 短縮形） | 有効桁数 | 指数範囲（最小〜最大） |
| --- | --- | --- | --- |
| `d32` | `d32`（`hm`） | 7 桁 | $-101 \sim +90$ |
| `d64` | `d64`（`m`） | 16 桁 | $-398 \sim +369$ |
| `d128` | `d128`（`M`） | 34 桁 | $-6176 \sim +6111$ |

サフィックスのない小数リテラルであっても、期待型が `d32` / `d64` / `d128` であれば 2 進変換を挟まずに 10 進リテラルとして直接符号化されます。範囲外のリテラルは `E1009`（`decimal_literal_out_of_range`）になります。

```tsuzuri run=f16%3D4.14%20f64%3D0.015%20exact%3Dtrue
let half = 4.14f16
let ratio = 1.5e-2
let sum = 0.1d64 + 0.2d64
$"f16={half} f64={ratio} exact={sum == 0.3d64}"
```

## 論理値リテラルと Unit リテラル

- **論理値 (`bool`)**: `true` と `false` の 2 つのみです。整数 `0` / `1` やポインタからの暗黙変換はありません。
- **Unit (`unit`)**: 空の丸括弧 `()` で表し、「意味のある戻り値が存在しないこと」を示します。`to_string ()` は `"()"` を返しますが、`Main.tz` の末尾のトップレベル式が `unit` 型の場合は標準出力へ何も出力されません。

## 文字・文字列・バイト列リテラル

文字リテラルは単一引用符 `'...'`、文字列リテラルは二重引用符 `"..."` で記述します。接頭辞 `u8` や接尾辞 `B` と引用符の間に空白を入れることはできません。

### 文字リテラル (`char`, `utf8char`, `byte`)

- **`'c'` (`char`)**: UTF-16 の 1 コード単位（`U+0000`〜`U+FFFF`）を表します。絵文字 `'😀'`（`U+1F600`）のようにサロゲートペア（2 コード単位）を要する文字を `char` リテラルに書くことはできず、`E0001`（`char_literal_not_one_unit`）になります。
- **`u8'c'` (`utf8char`)**: サロゲート領域（`U+D800`〜`U+DFFF`）を除く 1 つの Unicode スカラー値（`U+0000`〜`U+10FFFF`）を表します。`u8'😀'` や `u8'あ'` を 1 文字として保持できます。なお、接頭辞形式 `u8'a'` のみが有効であり、後置の `'a'u8` は `E0001` になります。
- **`'c'B` (`byte` / `i8u`)**: ASCII 範囲（`U+0000`〜`U+007F`）の 1 文字を符号なし 8 ビット整数リテラルとして表します（`'A'B` は `65i8u` と等価です）。非 ASCII 文字 `'あ'B` や、`u8` と組み合わせた `u8'A'B` は `E0001` になります。

文字リテラル内で使用できるエスケープは `\'`、`\\`、`\n`、`\r`、`\t`、`\0`、`\uXXXX`（`char` のみ、4 桁 16 進）、および `\u{...}`（`char` は `0xFFFF` 以下、`utf8char` はサロゲートを除く 1〜6 桁の `0x10FFFF` 以下）です。

### 文字列・バイト配列・スカラー配列リテラル

- **`"..."` (`string`) / `u8"..."` (`utf8string`)**: それぞれ UTF-16 コード単位列と妥当な UTF-8 バイト列を生成します。型注釈によって両者が自動変換されることはありません。式を埋め込む補間文字列は `$"..."` および `u8$"..."` を使用します。
- **`"..."B` (`[byte]`)**: ASCII 文字のみを含む文字列リテラルに `B` サフィックスを付けると、各バイトを要素とする配列 `[byte]`（`[i8u]`）になります。非 ASCII 文字を含む場合は `E0001`（`byte_literal_not_ascii`）になります。
- **`u8"..."B` (`[utf8char]`)**: `u8"..."` リテラルに `B` サフィックスを付けると、UTF-8 文字列を構成する各 Unicode スカラーを並べた配列 `[utf8char]` になります。補間文字列（`$"..."B`）に `B` サフィックスを付けることはできません（`E0001`）。

```tsuzuri run=byte%3D65%20bytes%3D%5B79%2C%2075%5D%20scalars%3D2
let code: byte = 'A'B
let packet = "OK"B
let emojis = u8"A😀"B
$"byte={code} bytes={packet} scalars={emojis.length}"
```

## コレクション・複合リテラル

### 配列 (`[T]`) と固定長配列 (`[T; N]`)

角括弧 `[e1, e2, ...]` は連続メモリ上の配列リテラルを構築します。

- 期待型が指定されていない場合、または `[T]`（`Array<T>`）が期待される場合は通常の配列 `[T]` になります。空配列 `[]` には要素型を決定できる型注釈または引数文脈が必要です。
- 期待型が固定長配列 `[T; N]`（`N` は `0`〜`1024` のコンパイル時整数定数）である場合、同じ `[e1, e2, ...]` 構文がインライン配置の固定長配列リテラルとして型検査されます。要素数が `N` と一致しない場合は `E1003`（`fixed_array_literal_length`）、`N` が `1024` を超える場合は `E1010` になります。
- `new [e1, e2, ...]` と記述すると関数フレームのスタックではなく最初からヒープ領域に確保されます（固定長配列に `new` は付けられません）。

### 連結リスト (`[|T|]`) とタプル

- **連結リスト (`[| ... |]`)**: 棒付き角括弧 `[| 10, 20, 30 |]` で不変リスト `[|T|]` を構築します。空リストは `[||]` です。`new [| 10, 20 |]` で直接ヒープチャンクとして確保できます。
- **タプル (`(a, b, ...)`)**: カンマ区切りの丸括弧 `(42, "ok", true)` で異種型の組（型表記は `i32 * string * bool`）を構築します。

```tsuzuri run=arr%3D60%20fixed%3D6%20list%3D30%20pair%3D42
let arr = [10, 20, 30]
let fixed: [i64; 3] = [1, 2, 3]
let items = [| 10i64, 20i64 |]
let pair = (42, "answer")
let list_sum =
    match items with
    | head :: tail -> head + List.sum tail
    | [||] -> 0
$"arr={Array.sum arr} fixed={Array.sum fixed} list={list_sum} pair={match pair with | (n, _) -> n}"
```

## コンパイル時定数 (`const`)

リテラルや基本演算、`const def` で定義した純粋なコンパイル時関数を組み合わせて名前付き定数を宣言するには `const Name: Type = 式` を使用します。配列やレコードなどの平坦なデータのみからなる定数はバイナリの読み取り専用静的領域に 1 つだけ配置され、実行時の再構築コストなしに参照・借用できます。

```tsuzuri run=144
const def square :: i64 -> i64 = \n -> n * n
const GridCells: i64 = square 12
GridCells
```
