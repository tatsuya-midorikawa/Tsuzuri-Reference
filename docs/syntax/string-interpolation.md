# 文字列補間と書式指定

補間文字列リテラル `$"..."`（`string` 型）および `u8$"..."`（`utf8string` 型）は、リテラル中の波括弧 `{式}`（穴）に任意の式の評価結果を埋め込んで文字列を構築する構文です。各穴の値は `Display` 型クラス（または独自書式を扱う `Format` 型クラス）によって文字列化され、すべての断片の長さを確定させたうえで 1 回のバッファ確保で結合されます。

数値の書式化と丸め処理はホスト OS の `printf` やロケール設定に一切依存せず Tsuzuri ランタイム自身が厳密な値から計算するため、ネイティブ実行と WebAssembly の間でビット単位で完全に同一の出力が得られます。

## 要点

- **2 種類の補間リテラルと波括弧エスケープ**: `$"..."` は `string`、`u8$"..."` は `utf8string` を生成します。文字としての `{` と `}` は `{{` と `}}` で記述します。
- **非消費の左から右への評価**: 穴は左から順に 1 回ずつ評価されます。ローカル変数やフィールドなどの場所（プレース）はムーブされず共有借用されるため、補間の後も元の変数を使い続けられます。
- **統一書式指定構文**: `{式:[[fill]align][+][width][.precision][type]}` により、文字埋め・左/右/中央揃え・正符号・最小幅・小数精度・基数変換（`x`/`X`/`b`/`o`）・指数/固定小数点表記（`e`/`f`）を静的に型検査したうえで適用できます。
- **`Format` 型クラスによる拡張**: ユーザー定義の `record` や `union` に `instance Format<T>` を実装すると、`+` や `.precision` を含む独自の書式指定子を受け取れます。

## 構文と字句規則

```text
$"text {expr} more"
$"text {expr:spec} more"
u8$"text {expr:spec} more"
```

- **接頭辞**: `$"` または `u8$"` と隙間なく記述します（`$` や `u8` の後ろに空白は置けません）。補間文字列にバイトサフィックス `B` を付けることはできません（`E0001`）。
- **波括弧のエスケープ**: リテラル本文で `{` を出力するには `{{`、`}` を出力するには `}}` と重ねて記述します。穴の外に単独の `}` を置くと `E0001`（`single_closing_brace_in_interpolation`）になります。穴を 1 つも含まない `$"a{{b}}"` は通常の静的文字列リテラル `"a{b}"` と等価に扱われます。
- **穴の記述制約**:
  - 各穴 `{ ... }` は **1 行以内**に収める必要があります。穴の内部での改行は `E0001`（`interpolation_hole_spans_lines`）、コメント（`//` や `/* ... */`）の記述は `E0001`（`comment_in_interpolation_hole`）になります。複雑な式は事前に `let` で束縛してから埋め込みます。
  - 穴の内部に文字列リテラルや別の補間文字列を入れ子にすることは可能です（構文ネスト上限 128 段まで）。
  - 空の穴 `$"{}"` は `E0002`（`empty_interpolation_hole`）、1 つの補間リテラル内の穴が 1,024 個を超えると `E0002`（`too_many_interpolation_holes`）になります。
- **書式区切りのコロン**: 穴の中で括弧 `()`・`[]`・`{}` の外側に現れる最初の単一コロン `:` が書式指定子の開始とみなされます（名前空間区切りやコンスパターンの `::`、括弧内の型注釈やレコード構築の `:` は書式を開始しません）。

```tsuzuri run=hello%20Tsuzuri%2C%20next%3D4%20%7Bok%7D
let name = "Tsuzuri"
let step = 3
$"hello {name}, next={step + 1} {{ok}}"
```

`u8$"..."` の場合も、各穴はいったん `Display` / `Format` によって `string` へ変換されたのち UTF-8 として結合されます。穴の文字列化結果に孤立サロゲートが含まれていた場合は実行時にトラップします。

## `Display` 型クラスと穴の所有権・借用規則

書式指定を省略した穴 `{expr}`（および幅・揃えのみを指定した穴）には、`Display` 型クラスの実装が必要です。`Display` を持たない型の値を埋め込むと `E1005` になります。ジェネリック関数内で型変数 `'a` の値を補間する場合は、関数シグネチャに `Display<'a> =>` 制約を付与します。

```mermaid
flowchart LR
    h1["穴 1..N を左から順に 1 回ずつ評価"] --> fmt["共有借用で Display / Format を呼び出し"]
    fmt --> alloc["全断片の合計長を検査し<br/>結果バッファを 1 回だけ確保して結合"]
```

組み込みの `to_string` と異なり、補間の穴は値を消費（ムーブ）せず共有借用で読み取ります。コンパイラは型付け後の穴の式を以下の 3 種類に分類して寿命を管理します。

| 穴の式の種類 | 代表例 | 所有権・借用の振る舞い |
| --- | --- | --- |
| **場所（プレース）** | `{s}`, `{user.name}`, `{xs[0]}`, `{deref r}` | その場所を直接共有借用する。非 `Copy` のローカル変数 `s` もムーブされず、補間式の後でそのまま再利用できる。共有借用は補間式全体の評価が終わるまで継続する |
| **非プレースの参照値** | `{ref x}`, `{ref mut y}` | `ref T` はそのまま渡し、`ref mut T` は共有参照として再借用する |
| **一時値（その他の式）** | `{s.length}`, `{s[0]}`, `{a + b}`, `{(make ()).title}` | その穴の位置で 1 回評価して内部の一時領域に保持し、全体の結合完了後に破棄する。元の変数への借用を後続の穴まで引きずらない |

```tsuzuri run=title%3DTsuzuri%287%29%20still_usable%3DTsuzuri
let title = "Tsuzuri"
let summary = $"title={title}({title.length})"
$"{summary} still_usable={title}"
```

### 所有権に関する境界条件

- **同一補間内での排他借用との競合**: プレースの穴 `{x}` の共有借用は補間式全体が終わるまで生存するため、同じ補間式の後続の穴で `$"{x} {mutate (ref mut x)}"` のように `x` を排他借用すると借用競合 `E1014` になります。一方、`$"{xs.length} {mutate (ref mut xs)}"` のように先行する穴が一時値であれば、評価時点で `xs` の読み取りが完了しているため競合しません。
- **一時値に対する明示 `ref` の禁止**: `{ref (f x)}` や `{ref s.length}` のように一時値へ明示的な `ref` を付けると `E1013` になります。`ref` を省いて `{f x}`・`{s.length}` と記述してください。
- **一時値からの非 `Copy` 要素抽出**: 関数呼び出し結果などの一時配列から非 `Copy` 要素を取り出す `{(names ())[0]}` や、`Drop` を実装する一時値から非 `Copy` フィールドを取り出す穴は部分ムーブ規則により `E1012` になります。いったん `let` で変数に束縛してからプレースとして埋め込みます。
- **条件分岐によるローカル移動**: `{if cond then a else b}` は一時値を生成する分岐式であるため、`a`・`b` が非 `Copy` のローカル変数である場合は選択された側の所有権が一時領域へムーブします（移動させたくない場合は `{if cond then ref a else ref b}` と参照で揃えます）。

## 書式指定子 (`[[fill]align][+][width][.precision][type]`)

穴のコロン `:` の直後に書式指定子を記述できます（コロン直後が空の `{x:}` は書式指定なしと同じ扱いになります）。

```text
[[fill]align][+][width][.precision][type]
```

### 各フィールドの仕様

| フィールド | 指定方法 | 詳細仕様 |
| --- | --- | --- |
| `fill` | `align` の直前に置く 1 つの Unicode スカラー文字 | 余白を埋めるパディング文字（既定は半角空白 `' '`）。`{`、`}`、`"`、`\`、改行（`\r` / `\n`）、および孤立サロゲートは指定不可（`E0001`）。絵文字などの補助平面スカラーも 1 文字として指定可能 |
| `align` | `<`（左寄せ）<br/>`>`（右寄せ）<br/>`^`（中央揃え） | 省略時は数値型が右寄せ、それ以外の型が左寄せ。中央揃え `^` で余白数が奇数の場合は左側を `余白 / 2`（切り捨て）、右側を 1 文字多く配置（例: `{"ab":*^5}` は `"*ab**"`） |
| `+` | `+` | `0` 以上の非負数値（`+0`、`+0.00`、`+inf` を含む）の先頭にも正符号 `+` を付与 |
| `width` | `1`〜`4096` の 10 進整数（先行ゼロ不可） | 最小表示幅（Unicode スカラー文字数単位）。フォーマット結果がすでに `width` 以上であれば切り詰めずそのまま出力。ゼロ埋めしたい場合は `{x:04}` ではなく `fill` + `align` を使って **`{x:0>4}`** と記述する（`{x:04}` は `E0001`） |
| `.precision` | `.0`〜`.4096` の 10 進整数（余分な先行ゼロ不可） | 2 進浮動小数点・10 進浮動小数点の精度指定。`.0` は有効だが `.05` のような先行ゼロは `E0001`。整数型には指定不可（`E0001`） |
| `type` | 整数用: `x`, `X`, `o`, `b`<br/>浮動小数点・decimal 用: `f`, `e` | `x`（小文字 16 進）、`X`（大文字 16 進）、`o`（8 進）、`b`（2 進）、`f`（固定小数点）、`e`（小文字指数表記）。`f` と `e` には `.precision` の併記が必須（`{v:e}` 単体は `E0001`）。大文字の指数指定 `E` は存在しない（`E0001`） |

幅（`width`）の計算はバイト数でも UTF-16 コード単位数でも東アジア全角幅でもなく、**出力文字列の Unicode スカラー数**で行われます。したがってサロゲートペアの絵文字 `"😀"`（2 コード単位）は 1 文字として数えられます（孤立サロゲートが存在する場合も 1 単位 1 文字として数えます）。

```tsuzuri run=%5B%20%20%207%5D%5B0007%5D%5B%2B42%5D%5B2a%5D%5B-FF%5D%5B1010%5D%5B10%5D%5B%2A%2A%F0%9F%98%80%5D
let emoji = "😀"
$"[{7:>4}][{7:0>4}][{42:+}][{42:x}][{-255:X}][{10:b}][{8:o}][{emoji:*>3}]"
```

### 型ごとの受理規則と数値丸めの契約

どの書式要素が使えるかは、穴の型（参照型 `ref T` の場合は参照先の `T`）によってコンパイル時に検査されます。未解決の型変数に対して `+`・`.precision`・`type` を指定した場合は `E1003`（`format_spec_type_unknown`）になります。

| 書式要素 | 使用可能な型 |
| --- | --- |
| `fill`, `align`, `width` | `Display` を実装するすべての型 |
| `+` | 固定幅整数（`i8`〜`i128`, `i8u`〜`i128u`）、2 進浮動小数点（`f16`〜`f128`）、10 進浮動小数点（`d32`〜`d128`）、または `Format` 実装型 |
| `x`, `X`, `o`, `b` | 固定幅整数（`i8`〜`i128`, `i8u`〜`i128u`）、または `Format` 実装型 |
| `.precision`, `f`, `e` | 2 進浮動小数点（`f16`〜`f128`）、10 進浮動小数点（`d32`〜`d128`）、または `Format` 実装型 |

- **整数の基数出力 (`x`, `X`, `o`, `b`)**: `0x` や `0b` などのプレフィックスは自動付与されません。負の符号付き整数は先頭に `-` を付けた絶対値で出力され、最小値（例: `-128i8` の `x` 指定 → `"-80"`）でもオーバーフローしません。
- **固定小数点 (`.Pf` または `.P`)**: `.precision` のみを書いて `type` を省略した `{v:.2}` は `{v:.2f}` と同義です。正確な実数値から小数点以下 $P$ 桁へ**最近接偶数丸め（ties-to-even）で 1 回だけ丸めます**。`P == 0` のときは小数点を出力しません（`2.5` → `"2"`、`3.5` → `"4"`）。
- **指数表記 (`.Pe`)**: 有効数字 $P + 1$ 桁へ最近接偶数丸めし、`d.dddeN` 形式で出力します（正の指数に `+` や先行ゼロは付けません。丸めによって桁上がりする `9.96` の `.1e` は `"1.0e1"`、`0.0` の `.2e` は `"0.00e0"` になります）。
- **特殊値と負のゼロ**: 負のゼロ `-0.0` は符号を保持して `"-0"`（`.2f` では `"-0.00"`）になります。非有限値は精度指定の有無にかかわらず `"inf"`（`+` 付きなら `"+inf"`）、`"-inf"`、`"nan"` と出力されます。

```tsuzuri run=0.12%7C0.38%7C2%7C4%7C-0.00%7C1.23e3%7C1.0e1
$"{0.125:.2}|{0.375:.2}|{2.5:.0}|{3.5:.0}|{-0.0:.2}|{1234.5:.2e}|{9.96:.1e}"
```

### 非サポートの書式構文

以下の表記は意図的に採用しておらず、記述するとコンパイルエラーになります。

- C の `printf` 形式（`%d`, `%s`）や `#` 代替フラグ（`0x` の自動付与は `$"0x{n:x}"` と明記します）
- 動的な幅・精度パラメータ（`{x:>{w}}` は `E0001` です。動的なパディングには `Format.pad` や `String.repeat` を使用します）
- ロケール依存の 3 桁カンマ区切りや通貨記号、大文字の指数指定子 `E`

## `Format` 型クラスによるカスタム書式

プログラム内で定義した `record` または `union` に対して `instance Format<T>` を実装すると、補間穴の書式指定文字列を受け取って独自のフォーマット処理を定義できます（プリミティブ型などに対する外部インスタンス定義はコヒーレンス規則 `E1016` で禁止されており、`deriving (Format)` はありません）。

```text
// 標準組み込みクラス Format のシグネチャ
def format :: ref 'a -> ref string -> string
```

レコードまたは共用体の値 `v` が書式付き穴 `{v:spec}` に置かれたとき、以下の規則で呼び出し先が決まります。

1. その型が `Format` インスタンスを持つ場合、正規化された書式文字列（省略要素や既定空白を除いた文字列。たとえば `{p: >10}` なら `">10"`、`{p:*>+8.2f}` なら `"*>+8.2f"`）が `Format.format` に渡されます。余白埋めもインスタンス側の責務となり、コンパイラは二重にパディングしません。
2. その型が `Format` インスタンスを持たず、指定が `fill`・`align`・`width` のみである場合は、`Display.display` の結果に対してコンパイラがパディングを行います。
3. その型が `Format` インスタンスを持たないにもかかわらず、`+`・`.precision`・`type` のいずれかを指定した場合は `E1005` になります。また、書式なしの穴 `{v}` は常に `Display` を呼ぶため、`Format` のみを実装して `Display` を実装していない型を `{v}` に置くと `E1005` になります。

書式文字列の分解とパディングには標準ライブラリの [`Format`](../stdlib/text/format.md) モジュール（`Format.parse` および `Format.pad`）を利用できます。

```tsuzuri run=%5B%20%20%20%20%20%201%2C2%5D%5B%2B1%2C2%5D%5B1%2C2%2F2%5D%5B%2A1%2C2%2A%2A%5D
record Point { x: i64, y: i64 }

instance Format<Point> {
    fn format point spec =
        match Format.parse spec with
        | Maybe.Some parsed ->
            let sign = if parsed.plus then "+" else ""
            let prec = if parsed.precision >= 0 then $"/{parsed.precision}" else ""
            Format.pad parsed $"{sign}{point.x},{point.y}{prec}"
        | Maybe.None -> ""
}

let p = Point { x: 1, y: 2 }
$"[{p:>9}][{p:+}][{p:.2}][{p:*^6}]"
```

## 診断コード一覧

文字列補間および書式指定に関連して報告される主な診断コードと `kind` は以下のとおりです。

| コード | 主な `kind` | 発生条件 |
| --- | --- | --- |
| `E0001` | `unterminated_interpolation_hole` | 穴の閉じ波括弧 `}` が欠落している |
| `E0001` | `single_closing_brace_in_interpolation` | 穴の外側にエスケープされていない単独の `}` がある（`}}` と記述する） |
| `E0001` | `interpolation_hole_spans_lines` | 穴 `{ ... }` の内部に改行が含まれている |
| `E0001` | `comment_in_interpolation_hole` | 穴 `{ ... }` の内部にコメントが記述されている |
| `E0001` | `byte_suffix_on_interpolated_string` | 補間文字列に `B` サフィックス（`$"..."B`）が付与されている |
| `E0001` | `invalid_format_spec` | 書式指定子が `[[fill]align][+][width][.precision][type]` の文法に合致しない（未知の型指定文字 `E` や不正な `fill` 文字など） |
| `E0001` | `format_field_out_of_range` | `width` または `precision` が `4096` を超えている、または先行ゼロ（`04`、`.05` 等）を含んでいる |
| `E0001` | `format_precision_on_integer` | 整数基数書式（`x`, `X`, `o`, `b`）に `.precision` を指定した |
| `E0001` | `format_type_needs_precision` | `e` または `f` 書式に `.precision` を指定していない（`.2e`, `.2f` のように記述する） |
| `E0002` | `empty_interpolation_hole` | 式を持たない空の穴 `$"{}"` を記述した |
| `E0002` | `too_many_interpolation_holes` | 1 つの補間文字列内の穴の数が上限（1,024 個）を超えた |
| `E0002` | `expected_interpolation_close` | 穴の中の式が構文的に完結せず `}` に到達しなかった |
| `E1003` | `format_spec_type_mismatch` | 穴の型が受け付けない書式要素を指定した（`string` に `:x`、整数に `:.2f` など） |
| `E1003` | `format_spec_type_unknown` | 具体型が確定していない型変数に数値専用書式（`+`, `.precision`, `type`）を指定した |
| `E1005` | （型クラス未実装） | 穴の型が `Display`（またはカスタム書式要求時の `Format`）を実装していない |
| `E1012` / `E1013` / `E1014` | （所有権・借用違反） | 一時値からの非 `Copy` 要素抽出、一時値への明示 `ref`、同一補間内でのプレース共有借用と排他借用の競合 |
| `E1016` | `format_instance_target` | 自パッケージ外の型やプリミティブ型に対して `instance Format<...>` を宣言した |
