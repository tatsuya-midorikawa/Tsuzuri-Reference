# プリミティブ型

プリミティブ型は、Tsuzuri コンパイラに直接組み込まれた最小単位の基本スカラー型です。8〜128 ビットの符号付き・符号なし固定幅整数、IEEE 754-2008 準拠の 2 進浮動小数点（`f16`〜`f128`）および 10 進浮動小数点（`d32`〜`d128`）、論理型 `bool`、ならびに UTF-16 と Unicode スカラー値の 2 系統の文字型（`char` / `utf8char`）で構成されます。すべてのプリミティブ型は `Copy` 型であり、ネイティブ実行と WebAssembly の双方でビット単位まで同一の演算規則を保証します。

## 要点

- **固定幅整数と既定型**: 符号付き `i8`〜`i128` と符号なし `i8u`〜`i128u` を備え、文脈から型が定まらない接尾辞なし整数リテラルの既定型は **`i32`** です（アーキテクチャ依存幅の `isize` / `usize` はありません）。
- **決定論的な整数算術**: 加減乗算とべき乗はビット幅でモジュロ折り返しを行い、ゼロ除算および符号付き最小値の `-1` 除算は未定義動作ではなく言語トラップ（`E2005`）となります。
- **2進浮動小数点と `f16` 経路**: `f16`・`f32`・`f64`（小数リテラルの既定型）・`f128` は IEEE 754 最近接偶数丸めに従い、`f16` はターゲットのハードウェア対応に関わらず 1 回丸めと quiet NaN 規則を厳密に一致させます。
- **10進浮動小数点（BID 表現）**: `d32`・`d64`・`d128` は IEEE 754-2008 の BID エンコーディングを採用し、`0.1d64 + 0.2d64 == 0.3d64` のように 10 進小数を丸め誤差なく表現します。
- **文字表現の明確な分離**: `char` は 16 bit UTF-16 コード単位、`utf8char` は検証済みの 32 bit Unicode スカラー値を表します（UTF-8 の個別バイトには `ubyte` / `i8u` を使用します）。

## プリミティブ型の一覧

すべてのローカル束縛は明示的な初期化が必須であり、未初期化変数が暗黙にゼロ値を持つことはありません。Edition 2028 ではリテラル接尾辞として型名そのもの（`42i64`、`255i8u`、`1.5f16`、`0.1d64`、および `BigInt` の `0I`）を使用します。旧来の短縮接尾辞（`l`、`uy`、`f`、`m` など）は Edition 2026 / 2027 の互換記法であり、Edition 2028 では `E0004` エラーとして拒否されます（`tsuzuri fix --edition 2028` で正規の型名接尾辞へ自動変換できます）。

| 型名（型別名） | サイズ | 表現範囲 / 精度 | リテラル例（Edition 2028 正規形） | 旧短縮接尾辞（2026 / 2027 のみ） | 概要 |
| --- | --- | --- | --- | --- | --- |
| `i8`（`sbyte`） | 8 bit (1 B) | $-128 \sim 127$ | `0i8`, `-5i8`, `0sbyte` | `y` | 符号付き 8 bit 整数 |
| `i16` | 16 bit (2 B) | $-32{,}768 \sim 32{,}767$ | `0i16` | `s` | 符号付き 16 bit 整数 |
| `i32` | 32 bit (4 B) | $-2{,}147{,}483{,}648 \sim 2{,}147{,}483{,}647$ | `0`, `42i32` | — | 符号付き 32 bit 整数（整数リテラルの既定型） |
| `i64` | 64 bit (8 B) | $-9{,}223{,}372{,}036{,}854{,}775{,}808 \sim 9{,}223{,}372{,}036{,}854{,}775{,}807$ | `0i64` | `l` | 符号付き 64 bit 整数（添字・要素数の標準型） |
| `i128` | 128 bit (16 B) | $-2^{127} \sim 2^{127} - 1$ | `0i128` | `L` | 符号付き 128 bit 整数 |
| `i8u`（`byte`, `ubyte`） | 8 bit (1 B) | $0 \sim 255$ | `0i8u`, `255ubyte` | `uy` | 符号なし 8 bit 整数・生バイト |
| `i16u` | 16 bit (2 B) | $0 \sim 65{,}535$ | `0i16u` | `us` | 符号なし 16 bit 整数 |
| `i32u` | 32 bit (4 B) | $0 \sim 4{,}294{,}967{,}295$ | `0i32u` | `u` | 符号なし 32 bit 整数 |
| `i64u` | 64 bit (8 B) | $0 \sim 18{,}446{,}744{,}073{,}709{,}551{,}615$ | `0i64u` | `ul` | 符号なし 64 bit 整数（`Hash.hash` の戻り値型） |
| `i128u` | 128 bit (16 B) | $0 \sim 2^{128} - 1$ | `0i128u` | `UL` | 符号なし 128 bit 整数 |
| `f16` | 16 bit (2 B) | IEEE 754 binary16（仮数 11 bit） | `0.0f16` | `hf` | 半精度 2 進浮動小数点数 |
| `f32` | 32 bit (4 B) | IEEE 754 binary32（仮数 24 bit） | `0.0f32` | `f` | 単精度 2 進浮動小数点数 |
| `f64` | 64 bit (8 B) | IEEE 754 binary64（仮数 53 bit） | `0.0`, `3.14f64` | — | 倍精度 2 進浮動小数点数（小数リテラルの既定型） |
| `f128` | 128 bit (16 B) | IEEE 754 binary128（仮数 113 bit） | `0.0f128` | `F` | 四倍精度 2 進浮動小数点数 |
| `d32` | 32 bit (4 B) | IEEE 754 decimal32（有効 7 桁、指数 $-101 \sim +90$） | `0.0d32` | `hm` | 単精度 10 進浮動小数点数（BID） |
| `d64` | 64 bit (8 B) | IEEE 754 decimal64（有効 16 桁、指数 $-398 \sim +369$） | `0.0d64` | `m` | 倍精度 10 進浮動小数点数（BID） |
| `d128` | 128 bit (16 B) | IEEE 754 decimal128（有効 34 桁、指数 $-6176 \sim +6111$） | `0.0d128` | `M` | 四倍精度 10 進浮動小数点数（BID） |
| `bool` | 8 bit (1 B) | `true` または `false` | `true`, `false` | — | 論理値 |
| `char` | 16 bit (2 B) | `0x0000` 〜 `0xFFFF` | `'A'`, `'\n'`, `'\uD800'` | — | UTF-16 コード単位（孤立サロゲートも保持可） |
| `utf8char` | 32 bit (4 B) | `U+0000` 〜 `U+10FFFF`（サロゲート除外） | `u8'A'`, `u8'😀'` | — | 検証済みの Unicode スカラー値 |

> [!NOTE]
> 大文字始まりの `Int`・`Math`・`Char`・`Utf8Char` はプリミティブ型名ではなく標準ライブラリのモジュール名です。

## 符号付き・符号なし整数型と既定型

### 型名の体系とポインタ幅の扱い

Tsuzuri の固定幅整数は、符号付きが `i8`・`i16`・`i32`・`i64`・`i128`、符号なしが末尾に `u` を付けた `i8u`・`i16u`・`i32u`・`i64u`・`i128u` です。8 ビット整数には `sbyte`（`= i8`）および `byte` / `ubyte`（`= i8u`）の組み込み別名が用意されています。`u8`〜`u128` という型名は存在しません。

また、ターゲット環境によってビット幅が変動する `isize` / `usize` 型も設けられていません。ネイティブターゲットはすべて 64 ビットアドレス空間を前提とし、WebAssembly（`wasm32` / `wasm64`）を含めてコレクションの要素数・添字・オフセットの標準 API はすべて **`i64`** に統一されています（なお、配列添字式 `xs[i]` 自体には任意の整数型を渡せます）。

### 整数リテラルの既定型

接尾辞を持たない整数リテラル（`42`、`1_000_000`、`0xFF` など）は、代入先の型注釈や後続の関数呼び出しから双方向に型推論されます。どの文脈からも型が一意に定まらない場合は、既定型の **`i32`** が選択されます。

文脈による型指定がないまま `i32` の表現範囲を超えるリテラル（例: `3_000_000_000`）を記述すると、範囲外エラー `E1009` になります。64 ビット以上の定数値には `3_000_000_000i64` のように接尾辞を付与するか、束縛側に型注釈を記述します。

### モジュロ折り返しと検査付き算術

固定幅整数の `+`、`-`、`*`、`**`、単項 `-`、およびビットシフト・論理演算は、2 の補数表現に基づくビット幅でのモジュロ折り返し（ラップアラウンド）として定義されており、C 言語の符号付きオーバーフローのような未定義動作は一切発生しません。

```tsuzuri run=-128:0:255
let wrapped_signed: i8 = 127i8 + 1i8
let wrapped_unsigned: i8u = 255i8u + 1i8u
let underflow_unsigned: i8u = 0i8u - 1i8u
$"{wrapped_signed as i64}:{wrapped_unsigned as i64}:{underflow_unsigned as i64}"
```

- 符号なし整数型は `Neg` 型クラスを持たないため、変数に対する単項 `-x` は `E1005`（`no instance for Neg<i8u>`）、負のリテラル `-1i8u` は範囲外エラー `E1009` になります。
- オーバーフローを検出したい場合は、式の直前に `@checked` を付けて `OverflowException` を送出させるか（[エラー処理](../expressions/error-handling.md)）、`Maybe` を返す [`Int.checked_add`](../stdlib/numeric/int.md) などの関数を使用します。

### 除算・剰余の言語トラップ

整数の除算 `/` と剰余 `%` において、以下の 2 条件は必ず言語トラップ（異常終了、`tsuzuri run` では `E2005`、WASM では `WebAssembly.RuntimeError`）を引き起こします。

1. **ゼロ除算**: `x / 0` または `x % 0`（`trap: integer division by zero`）
2. **符号付き最小値の `-1` 除算・剰余**: 各符号付き整数型の最小値（`i8` なら `-128i8`、`i32` なら `-2147483648`）を `-1` で割る、または剰余を取る操作（商が型の最大値を 1 超えるため `trap: integer division overflow`）

言語トラップは `try ... with` では捕捉できません。失敗し得る除算を安全に扱うには `Int.checked_div` / `Int.checked_rem` を使用します。

### 任意精度整数 `bigint`（`BigInt`）への導線

128 ビットを超える任意精度の整数計算には、リテラル接尾辞 `I`（例: `0I`、`10I ** 100`）と標準ライブラリの [`BigInt`](../stdlib/numeric/bigint.md) 型を使用します。

```tsuzuri run=1267650600228229401496703205376
def double_big :: BigInt -> BigInt = \n -> n * 2I

let base: bigint = 2I
double_big (base ** 99)
```

ローカル束縛の型注釈では小文字の `let x: bigint = ...` も記述できますが、トップレベル関数 `def` のシグネチャや `record` フィールドなどの型宣言位置では正規のレコード名である **`BigInt`** を使用します（シグネチャ位置に `bigint` と書くと `E1004` になります）。

## 2進浮動小数点型（`f16`・`f32`・`f64`・`f128`）

2 進浮動小数点型は IEEE 754-2008 の最近接偶数丸め（roundTiesToEven）に従います。コンパイラが勝手に `fast-math`（再結合や NaN 無視、暗黙の FMA 融合）を有効化することはありません。接尾辞のない小数リテラル（`3.14`、`1.0e-5`）は、文脈から他の浮動小数点型が期待されない限り **`f64`** となります。

- **非数（`nan`）と無限大（`inf` / `-inf`）**: 浮動小数点のゼロ除算はトラップせず、`1.0 / 0.0` は `inf`、`-1.0 / 0.0` は `-inf`、`0.0 / 0.0` は `nan` を生成します。`nan == nan` は常に `false`、`nan != nan` は `true` です（判定には [`Math.is_nan`](../stdlib/numeric/math.md) や `Math.is_finite` を使用します）。
- **符号付きゼロ**: `+0.0 == -0.0` は `true` と判定されますが、符号ビットは保持されます（`1.0 / -0.0` は `-inf` になり、`Math.copysign` で識別できます）。
- **初等超越関数**: `Math.sin`、`Math.exp`、`Math.log` などの超越関数は `Elementary<'a>` 制約を持つ **`f32` と `f64` のみ**が対象であり、ホスト OS の libm に依存しない同梱の決定論的実装（musl ベース）で計算されます。`f16`・`f128`・10 進浮動小数点型に対して呼び出すと `E1005` になります。

```tsuzuri run=false:true:-inf
let nan_val = 0.0 / 0.0
let pos_inf = 1.0 / 0.0
let neg_inf = 1.0 / -0.0
$"{nan_val == nan_val}:{Math.is_infinite pos_inf}:{neg_inf}"
```

### `f16` の計算経路とビット一致保証

半精度浮動小数点 `f16` の四則演算・比較・`Math.sqrt`、および `f32` / `f64` との `as` キャストは、ターゲットアーキテクチャと `--cpu` オプションに応じてコンパイル時にハードウェア命令または同梱の整数ベースソフトウェア実装のいずれかが選択されます。`f64` に拡大変換して演算するような二重丸めは行わず、**どのターゲット・経路でも結果のビット列が完全に一致**します。

| ターゲットと `--cpu` 設定 | 四則演算・比較・`Math.sqrt` | `f32` / `f64` との `as` 変換 |
| --- | --- | --- |
| AArch64（macOS / Linux / Windows、`--cpu generic`・`native` 共通） | LLVM `half` ハードウェア経路 | ハードウェア命令（`f64 as f16` も 1 回丸め） |
| x86-64（`--cpu native` かつ AVX512-FP16 対応 CPU） | LLVM `half` ハードウェア経路 | ハードウェア命令 |
| x86-64（`--cpu native` かつ F16C 対応 CPU） | ソフトウェア実装 | `f16` ↔ `f32`・`f16 as f64` のみ F16C 命令、`f64 as f16` は二重丸め回避のためソフトウェア実装 |
| x86-64 既定（`--cpu generic`）・F16C 非対応 CPU | ソフトウェア実装 | ソフトウェア実装 |
| WebAssembly（`wasm32` / `wasm64`） | ソフトウェア実装 | ソフトウェア実装 |

いずれの経路でも以下の意味論が厳密に保たれます。

- 非正規化数（subnormal）と符号付きゼロを保持し、`a * b + c` は乗算と加算で個別に丸めます（融合積和は明示的な `Math.fma` のみ）。
- 演算結果が `nan` となる場合はペイロードを消去した正規化 quiet NaN を生成し、符号ビットは `+` / `-` では左辺、`*` / `/` では両辺の排他的論理和となります。`Math.sqrt` は負の入力に対して正の quiet NaN を返し、`as` キャストは入力 NaN の符号を維持します。

```tsuzuri run=3.75:1.5:65504
let a = 1.5f16
let b = 2.25f16
let sum = (a + b) as f32
let root = (Math.sqrt b) as f32
let max_finite = 65519.0f32 as f16 as f32
$"{sum}:{root}:{max_finite}"
```

## 10進浮動小数点型（`d32`・`d64`・`d128`）

IEEE 754-2008 規格は 10 進浮動小数点の符号化方式として DPD（Densely Packed Decimal）と BID（Binary Integer Decimal）の 2 種類を定めており、Tsuzuri はソフトウェアおよびハードウェア双方での高速かつ決定論的な処理に適した **BID（2進整数仮数表現）** を採用しています。ネイティブ環境と WebAssembly 環境の双方で同一の同梱演算ルーチンを使用し、環境に依存しない厳密な IEEE 754-2008 十進算術を提供します。

2 進浮動小数点では `0.1 + 0.2` が循環 2 進小数となって微小な丸め誤差を生じますが、10 進浮動小数点では $c \times 10^q$ の形式で 10 進の有限小数を正確に保持できるため、金額計算・税率計算・計測値の集計に適しています。

```tsuzuri run=true:true:0.3
let unit_price: d64 = 0.10d64
let tax_added = unit_price + 0.20d64
let exact_sum = (0.1d128 + 0.2d128) == 0.3d128
let same_cohort = 1.0d64 == 1.00d64
$"{exact_sum}:{same_cohort}:{tax_added}"
```

- **有効桁数**: `d32` は 10 進 7 桁、`d64` は 16 桁、`d128` は 34 桁の固定精度仮数を持ちます（桁数無制限の有理数型ではありません）。有効桁数を超える演算結果は IEEE 754 の最近接偶数丸めに従って丸められます。
- **等値比較とコホート**: `1.0d64 == 1.00d64` のように末尾ゼロの指数表現（コホート）が異なる等しい数値同士の `==` は `true` となり、`Hash.hash` も正規化された同一のハッシュ値を返します。

## 論理型 `bool`

`bool` は `true` と `false` の 2 値のみを取る 1 バイトの型です。

- **論理演算子**: 論理否定 `!x`、短絡評価の論理積 `a && b`（`a` が `false` なら `b` を評価しない）、短絡評価の論理和 `a || b`（`a` が `true` なら `b` を評価しない）を使用します。
- **暗黙変換と順序比較の非存在**: `if` や `while` の条件式には必ず `bool` 型が必要であり、整数 `0` や空文字列 `""` を条件式に書くことはできません（`E1003`）。また `bool as i32` のような数値キャストや `false < true` のような順序比較（`Ord<bool>`）は定義されておらず、`E1005` になります。数値へ変換する場合は `if flag then 1 else 0` と明示します。

```tsuzuri run=1:false
let flag = true
let code = if flag && !(10 == 20) then 1 else 0
$"{code}:{!flag}"
```

## 文字型 `char` と `utf8char`

Tsuzuri は文字列の内部表現に合わせて 2 種類の文字プリミティブ型を備えています。両者を暗黙に混在させることはできません。

| 型 | ビット幅 | 表現対象 | 対応する文字列型 | リテラル構文 |
| --- | --- | --- | --- | --- |
| `char` | 16 bit (2 B) | UTF-16 コード単位（`0x0000`〜`0xFFFF`、孤立サロゲートを含む全 65,536 値） | `string` | `'A'`, `'あ'`, `'\uD800'` |
| `utf8char` | 32 bit (4 B) | 検証済み Unicode スカラー値（`U+0000`〜`U+D7FF`, `U+E000`〜`U+10FFFF`） | `utf8string` | `u8'A'`, `u8'あ'`, `u8'😀'` |

- **`char` と BMP 外の文字**: `char` は 1 つの UTF-16 コード単位を表すため、サロゲートペアを必要とする絵文字（`U+1F600` など）を単一の `char` リテラルに書くことはできません。BMP 外のコードポイントを 1 文字値として扱う場合は 32 ビットの **`utf8char`**（`u8'😀'`）を使用します。
- **UTF-8 バイト単位との違い**: `utf8string` の添字アクセス `u8s[i]` が返す UTF-8 の生バイト（1 バイトコード単位）の型は `utf8char` ではなく **`ubyte`（`i8u`）** です。`utf8string` からデコードされた Unicode スカラー値を取り出すには [`Utf8String`](../stdlib/text/utf8string.md) のデコード関数を使用します。
- **数値との相互変換**: `char` や `utf8char` は `Numeric` 型クラスを持たないため、`as` 演算子による整数キャストは行えません（`E1005`）。コード値との変換には [`Char.to_u16` / `Char.of_u16`](../stdlib/text/char.md) および `Utf8Char.to_u32` / `Utf8Char.of_u32` を使用します。

```tsuzuri run=65:2:4:128512
let ascii: char = 'A'
let scalar: utf8char = u8'😀'
let utf16_text: string = "😀"
let utf8_text: utf8string = u8"😀"

$"{Char.to_u16 ascii as i64}:{utf16_text.length}:{utf8_text.length}:{Utf8Char.to_u32 scalar as i64}"
```
