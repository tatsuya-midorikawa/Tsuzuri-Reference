# 演算子と式

Tsuzuri のすべての演算子は式として値を返し、16 段階の優先順位と左から右への正格な評価順序が言語仕様として厳密に定義されています。最適化レベル（`-O0` / `-O3`）によって評価順序が入れ替わったり、言語トラップを伴う演算が除去されたりすることはありません。

## 要点

- 演算子の優先順位は順位 1（最も弱いパイプライン `|>`）から順位 16（最も強い関数適用・フィールド参照・添字）までの 16 段階です。
- 二項演算子のうちべき乗 `**` のみが右結合であり、その他の二項演算子はすべて左結合です。比較演算子は連鎖しません。
- 整数演算は既定でビット幅に応じて折り返します（未定義動作はありません）。オーバーフローを例外として検出したい式には `@checked` を付与します。
- 整数のゼロ除算、符号付き最小値の `-1` による除算、負の整数指数は `@checked` の有無によらず言語トラップとなります。
- 算術・比較・ビット・論理演算子は参照オペランド（`(ref a) + (ref b)` や借用引数同士の演算）を直接受け付け、`string` や `BigInt` などを複製・消費せずに扱えます。
- 添字とスライスは「基底 → 各キー成分（左から右）」の順に評価され、キー評価中の基底の変更は `E1014` で禁止されます。Edition 2028 では末尾相対位置 `^k`、範囲演算子群、多次元添字 `a[i, j]`、およびビュー添字に対する `ref` 明示規則（`E1042`）が統一されています。

## 演算子の優先順位と結合性

結合強度が弱い順（順位 1 が最弱、順位 16 が最強）に全演算子を示します。

| 順位 | 演算子 | 結合性 | 分類・意味 | 記述例 |
| --- | --- | --- | --- | --- |
| 1 | `\|>` | 左結合 | パイプライン（左辺の値を右辺の関数へ渡す） | `xs \|> Array.sum` |
| 2 | `>>`, `<<` | 左結合 | 関数合成（`>>` は前方合成、`<<` は後方合成） | `parse >> validate` |
| 3 | `\|\|` | 左結合 | 短絡論理和 | `ready \|\| fallback` |
| 4 | `&&` | 左結合 | 短絡論理積 | `valid && active` |
| 5 | `\|\|\|`, `\|` | 左結合 | ビット論理和（OR） | `flags \|\|\| 0x08` |
| 6 | `^^^`, `^` | 左結合 | ビット排他的論理和（XOR） | `mask ^^^ 0xFF` |
| 7 | `&&&`, `&` | 左結合 | ビット論理積（AND） | `bits &&& 0x0F` |
| 8 | `==`, `!=` | 左結合 | 等値比較・非等値比較 | `a == b`, `a != b` |
| 9 | `<`, `<=`, `>`, `>=` | 左結合 | 順序比較（連鎖不可） | `0 <= i && i < n` |
| 10 | `<<<`, `>>>` | 左結合 | ビット左シフト・右シフト | `bits >>> 2` |
| 11 | `+`, `-` | 左結合 | 加算（および文字列連結）・減算 | `base + offset` |
| 12 | `*`, `/`, `%` | 左結合 | 乗算・除算・剰余 | `total * factor` |
| 13 | `**` | **右結合** | べき乗（指数演算） | `2 ** 3 ** 2` |
| 14 | `as Type` | 左結合 | 明示的な数値型キャスト | `count as f64` |
| 15 | `-`, `+`, `!`, `~~~`, `~`<br/>`ref`, `ref mut`, `deref` | 単項前置 | 符号反転、単項正、論理否定、ビット反転<br/>共有借用、排他借用、参照外し | `-x`, `!done`, `~~~mask`<br/>`ref xs`, `deref ptr` |
| 16 | 空白適用 `f x`<br/>`.field`, `[index]` | 左結合 | 関数呼び出し・部分適用<br/>フィールド参照・添字・多次元添字・スライス | `add 10 20`<br/>`user.name`, `m[i, j]` |

- **代入との優先関係**: 再代入 `=` は上記のどの二項演算子よりも弱く結合します。
- **改行をまたぐ継続**: 二項演算子の直後で改行するか、次行の先頭に `|>`・`>>`・`<<`・`||`・`&&` を置くと、前の行の式への継続として解析されます。空白による関数適用は改行をまたぎません。
- **比較の非連鎖性**: `1 < x < 10` は `(1 < x) < 10` と解釈され、`bool` と整数の比較となるため `E1003` になります。範囲判定は `1 < x && x < 10` と記述します。
- **借用・参照外しの正準記法**: Edition 2027 以降（既定の Edition 2028 を含む）では、借用と参照外しにキーワード `ref`・`ref mut`・`deref` を用います（旧記号 `&`・`&mut`・`*` は Edition 2026 の互換記法であり、Edition 2027 以降では `E0004` になります）。後ろに別の引数が続く場合は `f (ref mut counter) 1` のように括弧で囲みます。

## 算術演算子とオーバーフロー・トラップ

### 基本算術とべき乗・除算丸め

```tsuzuri run=pow%3D512%20unary%3D4%20div%3D-3%20rem%3D-1
let pow = 2 ** 3 ** 2
let unary = -2 ** 2
let div = -7 / 2
let rem = -7 % 2

$"pow={pow} unary={unary} div={div} rem={rem}"
```

- **単項負符号とべき乗**: 単項 `-`（順位 15）は `**`（順位 13）より強く結合するため、`-2 ** 2` は `(-2) ** 2` として評価され `4` になります。`-(2 ** 2)` を意図する場合は括弧を明示します。
- **右結合のべき乗**: `2 ** 3 ** 2` は `2 ** (3 ** 2)` すなわち $2^9 = 512$ です。スカラー型では整数型・`f32`・`f64`・`BigInt` が `Pow` インスタンスを持ちます（`f16` と `f128` には `Pow` がなく `E1005`）。`Tensor` などの型では演算子の拡張インスタンスにより `x ** 2` のような異種型間のべき乗も定義されています。
- **整数の除算と剰余**: `/` はゼロ方向へ切り捨て、`%` は被除数（左辺）と同じ符号を持ちます（`a == (a / b) * b + (a % b)` が常に成立します）。

### 整数の折り返しと @checked

通常の整数算術演算（`+`、`-`、`*`、`**`、単項 `-`）は、C 言語のような未定義動作を持たず、その整数型のビット幅（2 の補数表現）で決定論的に折り返します。ハッシュ計算や乱数生成のように折り返し自体が意図された処理では、`Int.wrapping_add`・`Int.wrapping_sub`・`Int.wrapping_mul`・`Int.wrapping_neg` を使うことで意図を明示でき、`--overflow-report`（`tsuzuri test` では既定で有効）による折り返し報告の対象から除外できます。

オーバーフローを折り返さずに検出したい式や文には、`@checked` 属性を前置します。`@checked` が直接覆う組み込み整数演算（`+`、`-`、`*`、`**`、単項 `-`）で桁あふれが発生すると `OverflowException` が送出され、同じ関数内の `try ... with` 式で `Result` として捕捉できます。

```tsuzuri run=wrapped%3D-2147483648%20caught%3DArithmetic%20operation%20resulted%20in%20an%20overflow.
def checked_inc :: i32 -> Result<i32, Exception> = \x ->
    try
        @checked (x + 1i32)
    with
    | e is OverflowException -> e

let wrapped: i32 = 2147483647i32 + 1i32
let msg =
    match checked_inc 2147483647i32 with
    | Ok _ -> "ok"
    | Error e -> e.msg

$"wrapped={wrapped} caught={msg}"
```

`@checked` が検査するのは付与された式・文の中に直接書かれた組み込み整数演算のみであり、そこから呼び出される別の関数本体までは波及しません。また、ゼロ除算も含め失敗を `Maybe` 値として受け取りたい場合は `Int.checked_add`・`Int.checked_div` などの標準ライブラリ関数を使用します。

### 整数の言語トラップ

以下の 3 つの整数演算は、`@checked` や `try` の有無にかかわらず即座に**言語トラップ**を引き起こし、プロセス（または `Domain.run` の隔離領域）を終了させます。

1. **ゼロ除算・ゼロ剰余**: `x / 0` または `x % 0`（`integer division by zero`）
2. **符号付き最小値の `-1` 除算**: `(-2147483648i32) / -1i32` や `(-2147483648i32) % -1i32` など、商が正の最大値を超える演算（`integer division overflow`）
3. **負の指数による整数べき乗**: 整数型の `base ** exp` において `exp < 0` の場合

## 浮動小数点演算（IEEE 754 と 10進浮動小数点）

### 2 進浮動小数点（f16・f32・f64・f128）

2 進浮動小数点型は IEEE 754 の最近接偶数丸め（roundTiesToEven）に従い、`NaN`、正負の無限大（`+inf` / `-inf`）、符号付きゼロ（`+0.0` / `-0.0`）、非正規化数をすべて保持します。コンパイラが勝手に結合法則を仮定して式を並び替える（fast-math）ことはありません。

```tsuzuri run=nan_eq%3Dfalse%20nan_neq%3Dtrue%20inf_gt%3Dtrue%20zero_eq%3Dtrue
let nan = 0.0 / 0.0
let inf = 1.0 / 0.0
let pos_zero = 0.0
let neg_zero = -0.0

$"nan_eq={nan == nan} nan_neq={nan != nan} inf_gt={inf > 1e300} zero_eq={pos_zero == neg_zero}"
```

- 浮動小数点のゼロ除算はトラップせず、`1.0 / 0.0` は `+inf`、`-1.0 / 0.0` は `-inf`、`0.0 / 0.0` は `NaN` になります。
- `NaN` との比較は `!=` のみが `true` を返し、`==`・`<`・`<=`・`>`・`>=` はすべて `false` を返します。
- `+0.0 == -0.0` は `true` ですが、符号ビットは保持されており `1.0 / +0.0` と `1.0 / -0.0` や `Math.copysign` では区別されます。
- 浮動小数点から整数への `as` キャストはゼロ方向へ切り捨て、表現範囲外の値は整数型の最小値・最大値へ飽和し、`NaN` は `0` に変換されます。

### 10 進浮動小数点（d32・d64・d128）

金額計算や税務計算など、2 進表現による丸め誤差（`0.1 + 0.2 != 0.3`）が許されない領域のために、IEEE 754-2008 準拠の 10 進浮動小数点型 `d32`・`d64`・`d128` が組み込まれています。四則演算と比較演算子をそのまま適用できます。

```tsuzuri run=true
let a = 0.1d64
let b = 0.2d64
a + b == 0.3d64
```

## ビット演算・比較・短絡論理演算

### ビット演算とシフト量マスク

ビット演算子は F# 互換の記号（`&&&`、`|||`、`^^^`、`~~~`）と C 風の記号（`&`、`|`、`^`、`~`）の双方を等価に受理します。`match` アームや関数ガードの直後など `|` が構文区切りと紛らわしい箇所では、`|||` を使うか括弧で囲みます。

```tsuzuri run=and%3D2%20or%3D7%20xor%3D5%20not%3D-11%20shl%3D16%20shr%3D-2
let a = 0b0110
let b = 0b0011

let bit_and = a &&& b
let bit_or = a ||| b
let bit_xor = a ^^^ b
let bit_not = ~~~10
let shl = 2 <<< 3
let shr = -8 >>> 2

$"and={bit_and} or={bit_or} xor={bit_xor} not={bit_not} shl={shl} shr={shr}"
```

- `<<<` は論理左シフトです。
- `>>>` は符号付き整数型では算術右シフト（符号拡張）、符号なし整数型では論理右シフト（ゼロ拡張）です。符号付き整数に対して論理右シフトを行う場合は `Bits.ushr` を使用します。
- シフト量はオペランドのビット幅でマスクされます（例: `i32` なら `shift & 31`、`i64` なら `shift & 63`）。ビット幅以上のシフトで未定義動作やトラップになることはありません。

### 等値・順序比較と短絡論理演算

- `==` と `!=` は同一のスカラー型・`unit`・文字列型のほか、`Eq` インスタンスを持つレコード・共用体・コレクションに使用できます。`<`・`<=`・`>`・`>=` は `Ord` インスタンスを持つ同一型間で比較します。異なる数値型間の暗黙変換はないため、`as` で型を揃えます。
- `&&` と `||` は左辺を先に評価する**短絡評価**を行います。`false && rhs` や `true || rhs` では `rhs` は一切評価されず、その中に副作用やゼロ除算があっても実行されません。
- 単項 `!` と組み込み関数 `not :: bool -> bool` はどちらも `bool` の論理否定であり、`not` はパイプライン（`flag |> not`）や高階関数への引数としてそのまま渡せます。

```tsuzuri run=true%20false
let safe = (false && (1 / 0 == 0)) || true
let inverted = safe |> not

$"{safe} {inverted}"
```

## パイプラインと関数合成

パイプライン演算子 `|>` は左辺の評価結果を右辺の関数の次の引数として渡し、関数合成演算子 `>>`（前方合成）と `<<`（後方合成）は 2 つの関数から新しい関数値を生成します。

```tsuzuri run=piped%3D12%20fwd%3D12%20bwd%3D12
def inc :: i64 -> i64 = \x -> x + 1
def dbl :: i64 -> i64 = \x -> x * 2

let piped = 5 |> inc |> dbl
let fwd = (inc >> dbl) 5
let bwd = (dbl << inc) 5

$"piped={piped} fwd={fwd} bwd={bwd}"
```

- `f >> g` は `\x -> g (f x)`、`g << f` は `\x -> g (f x)` と等価であり、合成演算子の両辺は左から右へ評価されます。
- 優先順位は `>>`・`<<`（順位 2）が `|>`（順位 1）より強いため、`5 |> inc >> dbl` は `5 |> (inc >> dbl)` と解釈されます。
- 標準ライブラリの関数は操作対象（コレクションや文字列など）を最後の引数に取る規約で統一されているため、`items |> Array.map f |> Array.sum` のように自然な左から右へのデータ変換パイプラインを記述できます。

## 参照オペランドへの対応

算術演算子（`+`、`-`、`*`、`/`、`%`、`*`、`**`、単項 `-`）、比較演算子（`==`、`!=`、`<`、`<=`、`>`、`>=`）、ビット演算子（`&&&`、`|||`、`^^^`、`<<<`、`>>>`、単項 `~~~`）、および論理演算子（`&&`、`||`、`!`）では、被演算子の型が共有参照 `ref T` または排他参照 `ref mut T` であり、`T` の先頭の型構築子が確定している場合、自動的に参照を 1 段外した `T` の演算として解決されます（`ref ref T` の場合は 1 段だけ外して `ref T` になります）。

両辺が参照である `(ref a) + (ref b)` だけでなく、参照と所有値が混在する `(ref a) + 1` や、Edition 2027/2028 の共有借用引数どうしの演算も、`deref` を書くことなくそのまま記述できます。

```tsuzuri run=joined%3Dhello!%20big%3D42%20mixed%3D50
def concat_pair :: string -> string -> string = \a b -> a + b

def calc_big :: BigInt -> BigInt -> BigInt = \x y -> (x + y) + 2I

def add_mixed :: ref i64 -> i64 -> i64 = \r v -> r + v

let left = "hello"
let right = "!"
let joined = concat_pair left right
let big = calc_big 20I 20I
let base: i64 = 30
let b2: i64 = 10
let mixed = (ref base) + (ref b2) + add_mixed (ref base) (-20)

$"joined={joined} big={big} mixed={mixed + left.length + right.length - 6}"
```

参照オペランドの所有権・メモリ上の振る舞いは次のとおりです。

- **借用で受け取る演算はゼロコピー**: `Eq`・`Ord` による比較、`BigInt`、利用者定義レコードの `Add` インスタンス、`Tensor` 演算など、被演算子を共有借用で受け取る演算子は元の参照をそのまま渡します。
- **文字列連結の非消費性**: 所有値の `s + "!"` は左辺 `s` を消費（ムーブ）しますが、参照オペランド `(ref s) + "!"`（および共有借用引数 `a + b`）は参照元を消費せず読み取って新しい文字列を生成するため、演算後も元の文字列変数をそのまま使用できます。
- **スカラー値の読み出し**: 整数・浮動小数点・`bool` など値を取るスカラー演算では `deref` と同じ読み出しが行われます（非 Copy 型を値で消費する演算に参照を渡した場合は `deref` と同じく `E1012` になります）。
- **対象外のケース**: 参照先が未解決の型変数（`ref 'a`）や未確定の推論変数（型注釈のない数値リテラル束縛 `let n = 30` の直後など）である被演算子には自動剥がしは適用されないため、参照先の型を確定させるか `deref left < deref right` のように明示します。また、`|>`・`>>`・`<<`・`as`・添字・代入 `=` は参照剥がしの対象外です。

## 添字・スライス・多次元添字と評価順序

### 式の評価順序と基底変更の禁止

Tsuzuri のあらゆる複合式は左から右へ正格評価されます。

| 構文 | 厳密な評価順序 |
| --- | --- |
| 二項演算 `a + b` | 左辺 `a` → 右辺 `b`（`&&`・`\|\|` は短絡評価） |
| 関数適用 `f a b` | 関数式 `f` → 引数 `a` → 引数 `b` |
| パイプライン `x \|> f` | 左辺 `x` → 関数式 `f` → 適用 |
| 配列・リスト・タプル | ソース上に記述された要素順（左から右へ 1 回ずつ） |
| レコード構築・更新 `{ r with f = a, g = b }` | 元レコード `r` → 記述順の各フィールド式 `a`, `b`（型宣言順ではない） |
| 代入 `target = rhs` | **右辺 `rhs` を先に評価** → 代入先 `target`（添字を含む）の評価 → 古い値の破棄と書き込み |
| 添字・スライス `base[c1, c2, ...]` | **基底 `base`** → **キー成分 `c1`, `c2`, ... を左から右**（範囲成分内は 始点 → 刻み → 終点） → 境界検査と読み出し |

添字やスライスのキー式を評価している間、基底 `base` は共有借用された状態になります。そのため `xs[xs.length - 1]` のようにキー式の中で基底を読み取ることは安全に行えますが、キーを評価する途中で基底へ再代入・ムーブ・排他借用（`ref mut`）を行うと借用競合エラー `E1014`（kind `borrow_conflict`）として静的に拒否されます。

### 範囲演算子と末尾相対位置（Edition 2028）

ブラケット `[...]` 内では、0 始まりの添字に加えて、Edition 2028 で統一された範囲演算子群と**末尾相対位置 `^k`** を記述できます。

| 記法 | 意味 | 備考 |
| --- | --- | --- |
| `xs[^0]` / `xs[^k]` | 末尾から数えた位置 `length - 1 - k` | `^0` が末尾要素、`^1` が末尾の 1 つ手前（Edition 2028）。ブラケット外や `for` 範囲では不可（`E0002`） |
| `ref xs[a..<b]` | 半開区間 $[a, b)$（終端を含まない） | 全エディション共通。片側省略 `ref xs[..<b]` も可 |
| `ref xs[a..=b]` | 閉区間 $[a, b]$（終端を含む） | 全エディション共通。片側省略 `ref xs[..=b]` も可 |
| `ref xs[a..b]` | Edition 2028 では閉区間 $[a, b]$ | Edition 2026/2027 では半開区間（`W1013`）。エディション非依存にするなら `..<` / `..=` を推奨 |
| `ref xs[a..]` | 始点 `a` から末尾まで | 全エディション共通 |
| `ref xs[a <.. b]` | 左開右閉区間 $(a, b]$（`a + 1` から `b` まで） | Edition 2028。始点必須・刻み指定不可 |
| `ref xs[a <..< b]` | 開区間 $(a, b)$（`a + 1` から `b - 1` まで） | Edition 2028。始点・終点ともに必須・刻み指定不可 |

```tsuzuri run=last%3D50%20penult%3D40%20mid%3D90
let xs = [10, 20, 30, 40, 50]
let last = xs[^0]
let penult = xs[^1]
let mid = Array.sum (ref xs[1 ..< ^0])

$"last={last} penult={penult} mid={mid}"
```

> [!WARNING]
> Tsuzuri の組み込み添字やスライス境界では、Python のように負の整数が末尾から数えられることはありません（負の添字は境界外トラップになります）。組み込み添字 `xs[-1]`、スライス境界 `ref xs[..-1]`、およびウィンドウ添字の位置指定 `ref t[-1, ..]` にゼロ以外の負の整数リテラルを書くと警告 `W1014` が出力されます。末尾からの指定には `^0` や `^1` を使用してください。また、前置 `^` はブラケット成分の先頭にのみ置け、`xs[k ^ 1]` のような中置の `^` はビット XOR として解釈されます。複合式を末尾オフセットにする場合は `xs[^(i + 1)]` のように括弧で囲みます。

### 多次元添字とビュー添字の ref 必須規則

`Matrix`、`MatrixView`、`Tensor`、`Map`、`HashMap`、および `Index` / `IndexMut` 型クラスを実装した利用者定義型では、カンマ区切りの多次元ブラケット添字 `a[i, j]` とスライス窓（ウィンドウ）を使用できます。

ブラケット添字は、キー成分の内容によって**要素モード**と**ウィンドウ（ビュー）モード**の 2 通りに解決されます。

1. **要素モード（範囲・`..`・`Slice.Sel` を含まない場合）**:
   - 成分が 1 個なら `Index<C, K, V>`、2〜4 個ならタプルキー `a[(i, j)]`、5 個以上なら配列キー `a[[i1, i2, i3, i4, i5]]` として解決されます。
   - `IndexMut` を実装する可変ビュー（`Tensor.Mut` や `MatrixView.Mut` など）では、`mt[i, j] = value` による要素代入も同じキー規則で動作します。
   - 組み込みの 1 次元コレクション（`[T]`、`[T; N]`、`[|T|]`、`Vec<T>`、`string`、`utf8string`）に 2 個以上の成分を渡すと `E1005`（`builtin_index_one_component`）になります。
2. **ウィンドウモード（範囲・単独 `..`・刻み範囲・`Slice.Sel` を 1 つ以上含む場合）**:
   - 各成分が厳密セレクタ `Slice.Sel`（`Item`、`Span`、`Whole`、残余軸を展開する `Slice.rest()` など）に変換され、基底データを借用するビュー（`MatrixView` や `Tensor.View` など）を返します。単独の `..` はその軸全体の選択を表します（ただし全成分を `..` のみにした `ref t[.., ..]` は `E0002` です）。
   - **ビュー添字の `ref` 必須規則**: 配列スライス `ref xs[a..<b]` と同様に、基底を借用するビューを返す添字式には必ず前置の **`ref`** を付ける必要があります（例: `ref m[0..<2, ..]`、`(ref t[1..<3, ..])[0, 1]`）。
     - 構文上の範囲や `..` を含みながら `ref` を省いた場合（`m[0..<2, ..]`）は `E0002`（`slice_must_be_borrowed`）になります。
     - `t[Slice.rest(), 0]` のように型解決の結果としてビューを返す `Index` インスタンスが選ばれたにもかかわらず `ref` がない場合は `E1042`（`index_view_requires_ref`）になります。
     - 読み取り専用のビューを返す添字に `ref mut` を付けた場合は `E1042`（`index_view_not_writable`）になります（要素の書き換えには `Tensor.borrow_mut` や `MatrixView.of_array_mut` を使います）。
     - 逆に、値を返す要素読み取りに対して `ref m[0, 1]` のように `ref` を付けると `E1003`（`index_ref_on_value`）になります。
   - `Index` / `IndexMut` や拡張演算子のインスタンス候補が複数合致して一意に定まらない場合は、暗黙の優先順位で選ぶことはせず `E1043`（`ambiguous_instance_candidates`）を報告します。リテラルへの型接尾辞（`0i64` など）や型注釈で解消します。

```tsuzuri run=elem%3D6%20row_sum%3D15%20sub_elem%3D5
let m = Matrix.of_array 3 3 [
    1, 2, 3,
    4, 5, 6,
    7, 8, 9
]

let elem = m[1, ^0]
let middle_row = ref m[1, ..]
let sub = ref m[0..<2, 1..=2]

$"elem={elem} row_sum={ middle_row[0, 0] + middle_row[0, 1] + middle_row[0, 2] } sub_elem={sub[1, 0]}"
```
