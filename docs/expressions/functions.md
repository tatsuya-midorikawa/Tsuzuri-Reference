# 関数

Tsuzuri において関数は第一級の値であり、複数引数の関数はすべてカリー化されています。`def` による明快な型シグネチャ宣言、不要な複製とムーブを抑える共有借用既定の引数規約、`-O0` でも保証される末尾再帰最適化、および副作用の不在を静的に検証する純粋関数 `pure def` を備えています。

## 要点

- 関数は `def 名前 :: 型 = \引数 -> 本体`（または `def` と `fn` の分離形式）で定義します。型区切りは `::` です。
- 引数を持たない `def answer :: i64` の呼び出し `answer()` と、`unit` を 1 つ受け取る `def f :: unit -> i64` の呼び出し `f ()` は明確に区別されます。
- すべての関数はカリー化されており、一部の引数だけを渡す部分適用、パイプライン `|>`、関数合成 `>>` / `<<` をそのまま利用できます。
- Edition 2027 以降（既定の Edition 2028 を含む）の通常の `def` では、無印の非 Copy 引数・型変数・関数型引数は**共有借用**として渡されます。所有権を受け取る場合は `own T`、呼び出し元の値を更新する場合は `mut T`（または `ref mut T`）を指定します。
- 再帰は `def rec`（ローカルでは `let rec`）と相互再帰の `and` で明示します。自己末尾再帰はループへ変換され、同一グループの相互末尾再帰も条件を満たせば一定のスタックで実行されます。
- `pure def` および純粋関数型 `pure (A -> B)` は、到達可能なすべての呼び出し先に外部副作用がないことをコンパイル時に検査します（違反は `E1029`）。

## 関数の宣言と呼び出し

### シグネチャと本体の記述形式

トップレベル関数は、`def` に続けて `::` で型シグネチャを記述し、`=` の右辺にラムダ式を置いて実装します。シグネチャの `def` と実装の `fn`（または `let`）を別の行に分けて書く形式も等価に受理されます。

```tsuzuri run=42
def add :: i64 -> i64 -> i64 = \left right ->
    left + right

def scale :: i64 -> i64 -> i64
fn scale factor value = factor * value

add 12 (scale 3 10)
```

- **型区切り記号**: `def` では必ず `::` を使用します（`:` を書くと構文エラー `E0002`）。
- **型矢印の右結合性**: `i64 -> i64 -> i64` は `i64 -> (i64 -> i64)` と同じです。関数を引数として受け取る高階関数では `(i64 -> i64) -> i64` のように括弧で囲みます。
- **引数適用と優先順位**: 空白による関数適用はどの二項演算子や単項 `-` よりも強く結合します。負のリテラルや複合式を渡す際は `shift (-1)` や `add (a + 1) (b * 2)` のように括弧を付けます。
- **可視性**: トップレベル関数は既定で他の Tsuzuri モジュールから `Module.func` として公開されます。モジュール内限定にする場合は `private def`、C ABI や WebAssembly ホスト向けに公開する場合は `export def` を用います。
- **オーバーロードの不在**: 同名で引数型だけが異なる関数を複数定義することはできません（重複宣言は `E1001`）。型に応じた多相的な振る舞いは[型クラスと制約](../types/type-classes.md)で表現します。

### 引数なし関数と unit 引数関数の違い

Tsuzuri では「引数を 0 個取る関数（型 `fn() -> R`）」と「`unit` 型の値を 1 個取る関数（型 `unit -> R`）」を区別します。

```tsuzuri run=42
def answer :: i64 = 40

def bonus :: unit -> i64 = \() -> 2

answer() + bonus ()
```

- `answer()`（識別子と `()` の間に空白なし）は引数 0 個の呼び出しです。
- `bonus ()` は `unit` リテラル `()` を 1 引数として渡す通常の関数適用です。`bonus()` のように引数 0 個で呼ぶとアリティ不一致エラー `E1006` になります。

## 関数ガードと where 節

ラムダ式の `->` の直後、または `fn` 形式の引数リストの直後に `|` 節を並べると、条件式やパターンによる**関数ガード**を記述できます。複数のガード節で共有する中間計算は、末尾の `where` 節にまとめられます。

```tsuzuri run=%E5%9C%A7%E5%8B%9D
def judge :: i64 -> i64 -> string = \left right ->
    | diff > 10 -> "圧勝"
    | diff > 5 -> "接戦"
    | otherwise -> "互角"
    where
        diff = Int.abs (left - right)

judge 30 18
```

- **条件節と網羅性**: `diff > 10` のような真偽値条件のみの節は網羅性検査に算入されないため、末尾に `otherwise` または `_` の無条件節が必要です（不足すると最初の `|` の位置に `E1021` が報告されます）。
- **パターン節**: パターン節を書く場合、1 引数ならその引数、複数引数（`\a b ->`）なら引数のタプル `(a, b)` に対する `match` と同じ規則で網羅性と所有権が検査されます。なお、ラムダ引数自体をパターンで分解した直後にパターン節を重ねると、非 Copy 値では二重照合となり `E1012` になります。
- **`where` 節の評価規則**: `where` は `|` と同じインデントの独立行に置き、その下に `let` を付けず `名前 [: 型] = 式` を深く揃えて並べます。`where` 内の束縛はガード判定が始まる前に上から順へ 1 回ずつ正格評価され、先行する `where` 束縛や関数の引数を参照できます（相互再帰や遅延評価ではありません）。

## カリー化・部分適用・パイプライン

複数引数の関数 `\a b -> body` は `\a -> \b -> body` と同じカリー化関数です。引数を一部だけ渡すと、残りの引数を待つ関数値が返ります。

```tsuzuri run=32
def multiply :: i64 -> i64 -> i64 = \factor value -> factor * value

let double = multiply 2
let numbers = [3, 5, 8]
let via_pipe = numbers |> Array.map double |> Array.sum
let via_compose = numbers |> (Array.map double >> Array.sum)

if via_pipe == via_compose then via_pipe else 0
```

- **標準ライブラリの引数順序との連携**: Tsuzuri の標準ライブラリは変換関数やキー・インデックスを先に受け取り、操作対象（コレクション、`string`、`Maybe`、`Result` など）を**最後の引数**に置く規約で統一されています（[標準ライブラリの設計規約](../stdlib/conventions.md)）。これにより `Array.map double` のような部分適用がそのまま `|>` や `>>` の構成要素になります。
- **関数値の Copy 性**: 通常の関数値自体は `Copy` であり、変数に束縛して複数回呼び出したりコピーしたりできます（環境捕捉の規則は[ラムダ式とクロージャ](./lambdas.md)を参照）。ただし、排他借用 `ref mut` を受け取る関数はその場で全引数を渡して完全適用する必要があり、排他借用を部分適用で閉じ込めた関数値を保存することはできません。
- **途中評価の段階**: `\a b -> body` は 2 つの引数が揃うまで `body` を評価しません。第 1 引数を渡した時点で前処理を実行してクロージャを返したい場合は、`\a -> { let pre = ...; \b -> ... }` のように明示的にネストしたラムダを返します。

## 引数規約（既定借用・own・mut・ref・ref mut）

Edition 2027 以降（既定の Edition 2028 を含む）の通常の `def`（および全エディションの `pure def`）では、所有権の不要な受け渡しや暗黙のディープコピーを防ぐため、シグネチャの型表記に応じて以下の引数規約が適用されます。

| シグネチャの表記 | 対象となる型 | 受け渡し規約 | 呼び出し側の所有権 | 本体での扱い |
| --- | --- | --- | --- | --- |
| 無印の `T` | 数値、`bool`、`unit`、`char`、解放不要な Copy レコード、`dyn`、SIMD | 値渡し | Copy 複製 | 通常のローカル値 |
| 無印の `T` | `string`、`[T]`、`[\|T\|]`、`Vec<T>`、解放を伴う複合型、型変数 `'a`、関数型 `A -> B` | **共有借用（読み取りビュー）** | **移動しない（呼び出し後も有効）** | `deref` 不要で値と同様に読み取り・演算子適用が可能 |
| `own T` | 任意の型 `T` | **所有権移動（値渡し）** | 非 Copy 値はムーブして消費 | 所有値として返却・格納・分解が可能 |
| `mut T` | 任意の型 `T`（トップレベル引数のみ） | **排他借用（変更ビュー）** | `let mut` 変数または `ref mut` を貸し出す | `deref` 不要でフィールド・要素への直接代入が可能 |
| `ref T` | 任意の型 `T` | 明示的な共有参照 | `ref x`（または関数呼び出しの一時借用） | `ref T` 型の参照値 |
| `ref mut T` | 任意の型 `T` | 明示的な排他参照 | `ref mut x` | `ref mut T` 型の参照値（全体置換は `deref r = v`） |

### 既定の共有借用と own T の使い分け

無印の `string` や配列引数は共有借用（`ref string` と同じ物理規約）として渡されるため、関数内で長さを調べたり演算子 `+` / `==` に渡したりしても、呼び出し元の変数は消費されません。引数をそのまま戻り値にしたりレコードへ格納したりして所有権を奪う関数では、`own T` を明示します。

```tsuzuri run=17
def greet :: string -> string -> string = \prefix name ->
    $"{prefix}, {name}!"

def into_excited :: own string -> string = \text ->
    text + "!!"

let user = "Tsuzuri"
let message = greet "Hello" user
let excited = into_excited message

excited.length + user.length - 7
```

裸の型変数 `'a` も既定で共有借用になるため、値をそのまま消費して返す恒等関数などは `def identity :: own 'a -> 'a = \x -> x` と記述します。

### 変更可能な引数（mut T）

引数全体の前に `mut` を付けた `mut T` は、排他参照の ABI を保ったまま本体で値ビューとして扱える構文です。呼び出し側は `let mut` で宣言した変数または既存の排他参照を渡せます。

```tsuzuri run=42
record Counter { value: i64 }

def add_step :: i64 -> mut Counter -> unit = \step counter ->
    counter.value = counter.value + step

let mut counter = Counter { value: 40 }
counter |> add_step 2
counter.value
```

`mut T` は関数のトップレベル引数にのみ記述でき、戻り値型やコールバック関数型の内部（`(mut Counter -> unit) -> unit` など）には書けません。コールバック型やレコードフィールドでは明示的な `ref mut Counter` を使用します。

なお、右辺のラムダ引数に `\(counter: ref mut Counter) -> ...`（共有借用引数なら `\(text: ref string) -> ...`）と参照型を注釈した場合は、値ビューではなく明示的な参照型のローカル変数として束縛されます。複数引数を注釈する場合はラムダをネストせず `\(a: ref string) (b: ref string) -> ...` のように 1 つのラムダに並べて記述します。

> [!NOTE]
> `const def`、エントリポイント `main`、`extern def`、型クラス `instance` のメソッド実装、および `Tsuzuri.toml` で `edition = "2026"` を指定したパッケージの通常の `def` では、無印の引数は従来の値渡し規約になります。また `\mut x ->` のようにラムダ仮引数側に付けた `mut` は「受け取ったローカル束縛を再代入可能にする」指定であり、値渡しになります。

## 再帰関数（def rec・let rec）と末尾再帰最適化

### def rec と相互再帰 and

自分自身を呼び出すトップレベル関数には `def rec` が必須です（`rec` のない再帰呼び出しは関数値や演算子経由の循環も含めて `E1019` として検出されます）。複数の関数が互いを呼び合う相互再帰は、`def rec` に続けて `and` で連結します。

```tsuzuri run=true
def rec is_even :: i64 -> bool = \n ->
    if n == 0 then true else is_odd (n - 1)
and is_odd :: i64 -> bool = \n ->
    if n == 0 then false else is_even (n - 1)

is_even 100000
```

`def` と `fn` を分離して書く場合も、双方に `rec` を揃えて `def rec name :: ...` / `fn rec name ... = ...` と記述します。

### 自己末尾再帰のループ変換と相互末尾呼び出し

Tsuzuri コンパイラは、最適化レベル `-O0` であっても以下の末尾呼び出し最適化を保証します。

1. **直接の自己末尾再帰のループ化**: 関数の末尾位置（`if`・`match`・関数ガード・末尾ブロックの各分岐末尾、および単項関数の `val |> self` を含む）にある自分自身への直接完全適用は、コンパイル時にループへ変換されます。借用を含む引数や借用を保持しうる関数値引数を取る場合はフレームを再利用できないため通常の呼び出しになります（ただしローカル `let rec` が外側から借用捕捉した変数をそのまま引き回す場合はループ化されます）。なお、2 引数以上のパイプライン `next |> self acc` はループ化されないため、`self acc next` と直接呼び出してください。
2. **同一再帰グループ内の保証された相互末尾呼び出し**: ネイティブターゲット（および `--wasm-feature tail-call` 指定時の WebAssembly）では、同じ `def rec ... and ...` グループ（または環境捕捉のない `let rec ... and ...` グループ）に属する別関数への末尾位置での直接完全適用は、以下の条件をすべて満たすときに呼び出し元スタックフレームを消費しない末尾呼び出しになります。
   - 両関数とも環境を捕捉せず、`tzroutine { ... }` 本体ではなく、`@cpu` による複数版を持たないこと
   - 引数と戻り値に借用（`ref` / `ref mut` や借用を保持しうる関数値）を含まないこと
   - 戻り値の型が `bool`・`unit`・`char`・`utf8char`、または 64 ビット幅以下の数値型（`i8`〜`i64`、`i8u`〜`i64u`、`f16`・`f32`・`f64`、`d32`・`d64`）であること（`i128`、`string`、配列、レコード、タプル、共用体などを返す相互再帰は通常の呼び出しとなり、戻り後にローカル所有値を解放します）
   - 保証された相互末尾呼び出しでは、実引数を左から右へ評価した直後・遷移先の関数が走る前に、呼び出し元が保持していた `Drop` 値などのローカル所有値が解放されます。

### ローカルな再帰関数（let rec）

関数本体やブロックの内部で、外側のローカル変数を参照しながら再帰する補助関数を作るには `let rec`（相互再帰は `and`）を使います。

```tsuzuri run=3
def count_above :: i64 -> [i64] -> i64 = \limit values ->
    let rec loop = \index found ->
        if index >= values.length then found
        elif values[index] > limit then loop (index + 1) (found + 1)
        else loop (index + 1) found
    loop 0 0

count_above 4 [5, 1, 9, 3, 7]
```

`let rec` は通常のラムダ式と異なり、外側の `string` や配列・`Vec` などの非 Copy 変数を**ムーブせず共有借用として捕捉**します。そのため、再帰のたびに配列を複製したり引数で引き回したりする必要がなく、ループ終了後も元の変数をそのまま使えます。その代わり、借用捕捉した値を `let rec` 本体内でムーブすることはできず（`E1012`）、借用を保持する `let rec` 関数値を所有者のスコープ外へ返すこともできません（`E1013`）。また、型変数 `'a` を含む型の値は捕捉できないため（`E1005`）、ジェネリック関数内の `let rec` には引数として渡します。

## 純粋関数（pure def と pure (A -> B)）

`pure def` は、外部世界への入出力や共有可変状態の操作を一切行わず、引数の値のみから結果が定まることをコンパイラが静的に検証する関数です。`private pure def`、`export pure def`、`pure def rec ... and ...`、および `@cpu` との併用が可能です（`const def` とは併用できません）。

```tsuzuri run=60
pure def weighted_sum :: i64 -> [i64] -> i64 = \weight values ->
    let mut acc = 0
    for x in values do
        acc = acc + x * weight
    acc

let items = [1, 2, 3]
weighted_sum 10 items
```

### 純粋関数の引数規則と禁止される効果

- **引数の所有権**: 無印の解放を伴う引数は全エディションで共有借用となり、`ref mut` や `mut T` 引数は使用できません。`own T` で所有権を受け取ることは可能ですが、外部から観測可能な副作用を防ぐため、数値・文字列・標準コレクションおよびそれらからなる**平たいデータ**の型に限定されます（参照、`Rc` / `Arc`、外部ハンドル、関数値、`dyn`、利用者定義の `Drop` 型を含む `own` 引数は `E1029` で拒否されます）。一方で、関数内部のローカルな `let mut` や新しい配列の生成は自由に行えます。
- **推移的な効果検査**: 関数が一度も呼ばれていなくても、`pure def` 本体およびそこから到達するすべての関数（通常の `def` を含む）が検査されます。違反時は `E1029`、到達関数数が 4,096 または式ノード数が 2,097,152 を超えた場合は `E1017` が報告されます。

| 分類 | `pure def` 内で許可される操作 | 禁止される操作（`E1029`） |
| --- | --- | --- |
| 状態とメモリ | ローカル `let mut`、新しい配列・文字列の生成 | `Atomic`、`Mutex`、`RwMutex`、`DataChannel`、`Rc` / `Arc` の操作、利用者 `Drop` 型の保持・破棄 |
| 入出力・乱数・時間 | 未実行の `IO<'a>` 値の構築（`IO.pure` / `IO.map`）、明示シードの `Random.pcg` | `IO` の実行、ファイル・OS・ネットワーク・無印 `extern`（`@trusted pure` を除く）、`Debug.print`、`Alloc` カウンタ観測、時計・OS 乱数 |
| 並行処理・動的呼び出し | 純粋なコールバックのみを用いた `Parallel.*` | `tzroutine { ... }`、`Routine.*`、`Time.after_func`、`Gpu.*`、`dyn` の構築と呼び出し、不透明な通常関数値 `A -> B` の呼び出し |

### 純粋関数型 pure (A -> B) とカリー化段階

コールバック引数や戻り値の関数型に対しても、呼び出しが純粋であることを表す型 **`pure (A -> B)`** を指定できます。純粋な関数値は通常の関数型 `A -> B` へ渡す（弱める）ことができますが、不透明な `A -> B` を `pure (A -> B)` として扱うことはできません。

```tsuzuri run=42
pure def apply_twice :: pure (i64 -> i64) -> i64 -> i64 = \f x ->
    f (f x)

pure def add_ten :: i64 -> i64 = \x -> x + 10

apply_twice add_ten 22
```

カリー化された純粋関数では、括弧の付け方によって純粋性が保証される呼び出し段階が変わります。

- `pure def f :: A -> B -> C`: `A` と `B` の両方を適用して `C` を計算する段階まで純粋性を保証します（本体は両方の引数を直接受け取る必要があります）。
- `pure def factory :: A -> (B -> C)`: `A` を受け取って関数を作る段階のみが純粋であり、返される関数は通常の `B -> C` です。
- `pure def factory :: A -> pure (B -> C)`: 関数を作る段階と、返された関数を呼び出す段階の双方に純粋性を保証します。

> [!NOTE]
> `pure` は「外部への副作用がないこと」を保証する契約であり、「トラップしないこと」や「必ず停止すること」を意味するものではありません。ゼロ除算や境界外アクセスは通常どおりトラップします。ヒープ確保の不在・論理トラップの不在・停止性まで静的に検証したい場合は、[契約と属性](./contracts-and-attributes.md)で解説する `@no_alloc`・`@no_trap`・`@terminates` や `tsuzuri prove` を併用します。
