# パターンマッチング

パターンマッチングは、データの構造・タグ・値を検査して分岐すると同時に、内部の要素やフィールドを安全に取り出す構文です。`match` 式を中心に、コンパイル時の厳密な網羅性検査（`E1021`）、到達不能アームの検出（`W1003`）、およびアフィン所有権・借用規則に基づいたゼロコピーの読み取りと最終使用ムーブ最適化が統合されています。

## 要点

- `match 対象式 with | パターン [when 条件] -> 結果式` は対象式を最初に 1 回だけ評価し、上から最初に成立したアームの式を評価してその値を返します。
- ワイルドカード、変数束縛、リテラル、タプル、レコード、判別共用体、配列、連結リスト（`[|...|]`・`head :: tail`）、匿名共用体の型テスト `:? T`、OR パターン `|`、AND パターン `&`、全体束縛 `as` を自由に組み合わせられます。
- 小文字または未知の単一識別子パターンはすべて**新しいローカル変数束縛**になります。既存の `const` 定数と等値比較したい場合は `| x when x == Limit ->` と記述します。
- `match` 式と関数ガードでは網羅性が静的に検査され、未処理ケースがあれば具体例付きで `E1021` になります（`when` ガード付きアームは網羅性に算入されません）。先行アームに完全に覆われた到達不能アームには警告 `W1003` が出ます。
- 所有値を分解すると非 Copy 要素をムーブでき、参照先を照合すると読み取り専用ビューが得られます。一時値や以後使われない所有変数を照合する場合、Copy 要素の配列等に対しても不要なディープコピーが省略されます。

## match 式の構文と評価順序

```text
match 対象式 with
| パターン1 -> 式1
| パターン2 when 条件式 -> 式2
| _ -> 既定の式
```

`match` 式は `対象式`（スクルーティニー）を最初に **1 回だけ**正格評価し、先頭のアームから順番にパターン照合を試みます。パターンが一致し、かつ `when` ガードがある場合はその条件式が `true` になった最初のアームの右辺式だけが評価され、`match` 全体の値になります。全アームの右辺式は同一の型でなければなりません（型不一致は `E1003`）。

```tsuzuri run=200
union Response = OkCode of i64 | Redirect of string | Failed

def status_number :: Response -> i64 = \resp ->
    match resp with
    | OkCode code -> code
    | Redirect _ -> 302
    | Failed -> 500

status_number (OkCode 200)
```

### パターンを使用できる構文と反駁可能性

パターンはすべての値に必ず一致する**反駁不可能パターン**（`_`、変数、反駁不可能要素のみのタプルやレコードなど）と、値によっては一致しない**反駁可能パターン**（リテラル、複数ケース共用体、配列・リスト、`:? T` など）に分かれます。使用箇所ごとの規則は次のとおりです。

| 使用箇所 | 反駁可能パターンの可否 | 網羅性・不一致時の扱い |
| --- | --- | --- |
| `match` 式 / `match!` 式 | 可 | 全ケース網羅が必須（不足は `E1021`） |
| 関数ガード（`\x -> \| pat -> ...`） | 可 | 全ケース網羅が必須（不足は `E1021`） |
| 不変の `let` 分解束縛 | **不可** | 反駁可能パターンは全エディションで `E1021` |
| ラムダ引数 / `for ... in` / `let!`・`and!` | **不可**（Edition 2027/2028） | Edition 2027/2028 では `E1021`（Edition 2026 では `W1012` のうえ不一致時にトラップ） |

## 全パターン種別リファレンス

| パターン種別 | 構文例 | 一致条件と束縛の動作 |
| --- | --- | --- |
| ワイルドカード | `_`, `otherwise` | 任意の値に一致し、束縛を作らない |
| 変数束縛 | `x`, `count` | 任意の値に一致し、ローカル変数へ束縛する |
| 型注釈付きパターン | `(x: i64)`, `(v: (i64 \| string))` | パターンに明示的な型を与える（匿名共用体型は内側の括弧が必要） |
| リテラルパターン | `0`, `"ok"`, `true`, `'a'`, `()` | `Eq`（`==`）による等値比較で一致を判定する |
| タプルパターン | `(x, y)`, `(0, rest)` | 要素数が一致し、各要素パターンがすべて一致する |
| レコードパターン | `Point { x = a, y = b }`, `{ x: a }` | 指定フィールドのみ照合する（未指定フィールドは無視。区切りは `=` / `:`、`,` / `;` いずれも可） |
| 判別共用体ケース | `Some v`, `None`, `Mod.Case (a, b)` | 共用体のタグを判定し、ペイロードを内側パターンへ渡す |
| 配列パターン | `[]`, `[a, b]`, `[first; second]` | 配列の要素数がちょうど一致し、各要素が一致する |
| リスト要素パターン | `[\|\|]`, `[\|a, b\|]` | 空リスト、または指定要素数の連結リストに一致する |
| リストコンスパターン | `head :: tail` | 空でない連結リストの先頭要素 `head` と残りリスト `tail` に分解する |
| 型テストパターン | `:? i64 as n`, `:? (i64 \| f64) as num` | 匿名共用体の実行時タグを判定し、`as` 変数へ要素型（または部分共用体型）の値を束縛する |
| OR パターン | `p1 \| p2` | 左辺 `p1` を先に試し、不一致なら `p2` を試す（両辺は同じ変数名・型を束縛する必要がある `E1020`） |
| AND パターン | `p1 & p2` | 同じ値に対して `p1` と `p2` の両方が一致し、双方の束縛を導入する |
| AS パターン（全体束縛） | `Some n as whole` | 内側パターン `Some n` の照合と同時に、一致した値全体を `whole` に束縛する |
| アクティブパターン | `Even`, `Parsed n`, `Divisible 3` | 認識器関数を呼び出して判定・変換する（詳細は[アクティブパターン](./active-patterns.md)） |

> [!WARNING]
> パターン内に書かれた単一の識別子（共用体のケース名でもアクティブパターン名でもない名前）は、たとえ同名の `const` 定数がスコープ内に存在していても、定数との等値比較ではなく**新しい変数束縛（すべてに一致するパターン）**として解釈されます。名前付き定数と比較したい場合は、必ず `| n when n == MaxLimit ->` のように `when` ガードを使用してください。

### 複合構造・配列・リストの照合例

```tsuzuri run=arr%3D30%20list%3D15
def sum_two_array :: [i64] -> i64 = \xs ->
    match xs with
    | [] -> 0
    | [only] -> only
    | [first, second] -> first + second
    | _ -> -1

def rec sum_list :: [|i64|] -> i64 = \items ->
    match items with
    | [||] -> 0
    | head :: tail -> head + sum_list tail

$"arr={sum_two_array [10, 20]} list={sum_list [|3, 5, 7|]}"
```

### 型テストパターン（`:? T`）と OR / AS パターンの例

[匿名共用体](../types/anonymous-unions.md)（例: `(i64 | f64 | string)`）に対しては、`:? 型 [as 変数]` で保持しているメンバー型を検査・抽出できます。`:? (i64 | f64) as num` のように部分集合となる匿名共用体型を書くと、該当メンバー群をまとめて小さな匿名共用体へ絞り込めます。

```tsuzuri run=num%20%2F%20str%3Ahi%20%2F%20pair%3A42
def classify_any :: own (i64 | f64 | string) -> string = \v ->
    match v with
    | :? (i64 | f64) -> "num"
    | :? string as s -> $"str:{s}"

union Item = Single of i64 | Pair of (i64 * i64)

def pick_main :: Item -> i64 = \item ->
    match item with
    | (Single n | Pair (n, _)) as _whole -> n

$"{classify_any 3.14} / {classify_any "hi"} / pair:{pick_main (Pair (42, 9))}"
```

## when ガードと評価中の読み取り専用ビュー

パターンの後ろに `when 条件式` を付けると、パターン一致後に追加の `bool` 条件を判定できます。条件が `false` の場合はそのアームは不成立となり、次のアームの照合へ移ります。

```tsuzuri run=adult
def age_group :: i64 -> string = \age ->
    match age with
    | n when n < 0 -> "invalid"
    | n when n < 18 -> "minor"
    | _ -> "adult"

age_group 24
```

- **ガード評価中の所有権保護**: `when` ガードを評価している時点ではまだそのアームの成立が確定していないため、パターンで束縛された変数は一時的な**読み取り専用ビュー**として扱われます。ガード式の中で非 Copy 値をムーブしたり書き換えたりすることは禁止されており、ガードが `false` になっても後続のアームが元の値を安全に照合できます。ガードが `true` になった時点で初めて正式な束縛（ムーブを含む）が確定します。
- **OR パターンと `when` の関係**: `| p1 | p2 when cond -> body` では、`p1` が一致した後に `cond` が `false` になった場合、同じアームの `p2` は再試行されず直ちに次のアームへ進みます。
- **ビット OR の括弧付け**: アーム内やガード式の中で中置 `|`（ビット OR）を使う場合は、OR パターンや次アームの区切りと区別するため `(flags | 0x01)` のように括弧で囲むか `|||` を使用します。

## 網羅性検査（E1021）と到達不能アーム警告（W1003）

### 網羅性検査（E1021）

コンパイラは `match` 式の入力型が取りうるすべての値が少なくとも 1 つの**ガードなしアーム**で覆われているかを静的に検証します。漏れがある場合はコンパイルエラー **`E1021`** となり、不足している具体的なパターン例が診断メッセージに提示されます。

- **有限領域の完全列挙**: `bool`（`true`・`false`）、`unit`（`()`）、判別共用体の全ケース、匿名共用体の全メンバーに対する `:? T`、連結リストの `[||]` と `head :: tail`、およびそれらのタプル・レコード直積は、ワイルドカード `_` なしですべて列挙できます。
- **広い領域の扱い**: 整数型（`i8` の全 256 値を並べた場合を含む）、浮動小数点型、文字列、配列パターン `[...]`、および匿名共用体に対するリテラルパターンは、有限個を列挙しても網羅とはみなされず、末尾に `_` または変数束縛が必要です。
- **`when` ガードの除外**: `when` ガード付きのアームは実行時に偽となりうるため網羅性のカバー範囲には数えられません。必ず後続にガードなしのフォールバック節を置いてください。

```text
// コンパイルエラー E1021: match is not exhaustive; missing: (false, false)
match (true, false) with
| (true, _) -> 1
| (_, true) -> 2
```

### 到達不能アーム警告（W1003）

先行するガードなしアームだけですべての入力ケースがすでに覆われており、後続のアームが絶対に実行されない場合は、到達不能アーム警告 **`W1003`**（kind `unreachable_match_arm`）が出力されます（先行アームに `when` ガードが付いている場合は後続へ進む可能性があるため警告されません）。

```text
// 警告 W1003: unreachable match arm; previous patterns already cover this arm
match Maybe.Some 10 with
| _ -> 0
| Maybe.Some n -> n
```

## 所有権・借用との相互作用とコピー省略

### 所有値のムーブ分解と借用先のビュー分解

- **所有値を照合する場合**: `let person = Person { name: "Ada", age: 30 }` のような所有値に対して `match person with`（または `own` 引数に対する `match`）を行うと、非 Copy フィールド `name` の所有権をパターン変数へそのままムーブできます（ムーブ後、元の `person` は消費済みになります）。
- **共有借用を照合する場合**: `match ref person with` や共有借用引数（Edition 2027/2028 の無印引数を含む）を照合する場合、非 Copy フィールドはアーム内部で有効な**読み取り専用ビュー**として束縛されます。複製を起こさずにフィールドの読み取りや関数渡しを行えますが、所有値として外へムーブしようとすると `E1012` になります。
- **二重ムーブの禁止**: 非 Copy 値に対して `Some s as whole` のように全体と内部ペイロードの両方を同時に所有値として束縛すると、二重消費となるため `E1012` で拒否されます（`match ref opt with` で借用照合するか、片方を `_` にします）。連結リストの `head :: tail` でも、非 Copy 要素リストから `tail` を所有値として取り出すことはできません（`E1012`）。

### 最終使用でのコピー省略

要素が Copy 型である配列 `[i64]` やリスト `[|i64|]` をペイロードに持つ共用体・タプル・レコードを `match` で分解する際、照合対象が**一時値**または**その `match` が最後の使用となるローカル所有変数**であれば、コンパイラはパターン変数への束縛時に要素配列のディープコピーを行わず、所有権のムーブとして直接引き渡します（`--warn implicit-copy` の警告 `W1006` も発生しません）。

```tsuzuri run=60
union Packet = Empty | Data of [i64]

def sum_packet :: own Packet -> i64 = \pkt ->
    match pkt with
    | Empty -> 0
    | Data values -> Array.sum (ref values)

sum_packet (Data [10, 20, 30])
```

なお、照合対象が後続のコードでも再び読まれる場合、`as` パターン等で記憶域が重なる場合、参照やリストの `tail` を経由する場合、または利用者定義の `Drop` を実装した型の内部から取り出す場合は、元の記憶域を安全に保つため通常どおりコピーが行われます。
