# ネイティブ連携と C ABI

Tsuzuri はガベージコレクタや重量級ランタイムへの依存なしに、標準的な C ABI を介して C / C++ / C# / Python / Rust などのホストプログラムと双方向に連携できます。`export def` は `tz_` 接頭辞付きの C 関数として公開され、`extern def` はホスト関数や既存の C ライブラリ関数を呼び出します。さらに、`tsuzuri bindgen` による C ヘッダーからの宣言自動生成、`--emit shared` と `--emit bindings-*` による共有ライブラリおよび各言語バインディングの自動生成、`--emit bitcode` による言語間 ThinLTO インライン化をサポートしています。

## 要点

- `--emit header` と `--emit object` を対で出力することで、C / C++ ホストから型安全なプロトタイプ宣言で Tsuzuri の関数をリンク・呼び出しできます。複数の Tsuzuri ライブラリのヘッダーを 1 つの翻訳単位で同時に `#include` することも可能です。
- 公開 ABI はスカラー数値・`bool`・`unit` 戻り値・借用スライス・所有バッファ・文字列・スカラーレコード・`@c_layout` 構造体・不透明ハンドル（`extern type`）・静的コールバックをサポートします。ホストへ返却された所有バッファは `tsuzuri_free` で 1 回だけ解放します。
- `extern type` にはムーブ専用の所有ハンドル、`copy`（非所有識別子）、`local`（OS スレッド拘束ハンドル）の 3 種があり、ネイティブでは `Maybe<Handle>` のゼロコスト NULL ニッチ表現や `ref mut`・`@count`・`ZString`・`extern view` を利用できます。
- macOS では Objective-C のクラスを `extern class` で型として宣言し、メソッドを型付きで呼び出せます（[Objective-C 連携](./objective-c.md)）。
- `tsuzuri bindgen` は Clang AST から ABI が厳密に一致する C 宣言のみを抽出し、不一致な宣言は推測せず `W2002` と `// skipped` コメントで明示します。
- `--emit shared` で `.dylib` / `.so` を生成し、`--emit bindings-cs`・`bindings-py`・`bindings-cpp` で C#（.NET 8 `LibraryImport`）・Python（`ctypes`）・C++20 の RAII バインディングを出力できます。

## 公開 C ABI で受け渡し可能な型

`export def add` は C シンボル `tz_add` として公開されます。Tsuzuri 内部ではカリー化された関数であっても、ABI 境界では全引数を一度に受け取るフラットな C 関数ラッパーが生成されます。

| Tsuzuri の型 | C ヘッダー上の表現 | 境界での規約 |
| --- | --- | --- |
| `i8` / `i16` / `i32` | `int32_t` | 8 / 16 bit 整数は境界で 32 bit に符号拡張・正規化 |
| `i8u` / `i16u` / `i32u` | `uint32_t` | 8 / 16 bit 符号なし整数は 32 bit にゼロ拡張・正規化 |
| `i64` / `i64u` | `int64_t` / `uint64_t` | 64 bit 整数そのまま |
| `f32` / `f64` | `float` / `double` | IEEE 754 単精度・倍精度そのまま |
| `bool` | `int32_t` | 入力は `0` が `false`、非ゼロが `true`。戻り値は `0` または `1` |
| `unit`（戻り値のみ） | `void` | `export def` は `unit` 引数を取れない（`E1008`）。引数なしの `export def f :: i64` は `int64_t tz_f(void)` となり、`extern def` の `unit` 引数は C 側で省略される |
| 共有借用バッファ（`ref [i64]`・`ref [f64]`・`ref [ubyte]`・`ref string`・`ref utf8string`） | `const T *arg_ptr, int64_t arg_len` | 呼び出し中のみ読み取り（複製も解放もしない）。`extern` では `@count` で長さ型を変更可能 |
| 所有戻り値（配列・`string`・`utf8string`） | 先頭引数 `tsuzuri_*_buffer *out`、戻り値 `void` | `{ ptr, len }` を書き込む。使用後はホストが `tsuzuri_free(out.ptr)` で解放 |
| スカラーレコード | 入力は `const tz_record_* *`、戻り値は先頭 out ポインタ | フィールドは宣言順に並び、狭い整数や `bool` は 32 bit に正規化 |
| `@c_layout` レコード | `extern def` の `ref` なしは C の値渡し・値返し（`tz_record_*` そのもの）。`ref R` は `const tz_record_* *`、`ref mut R` は `tz_record_* *`。`export def` は入力が `const tz_record_* *`、結果が先頭の out ポインター | C の構造体とバイト単位で一致するフィールド型・アライメント・パディング |
| 不透明ハンドル（`extern type`） | `typedef struct tz_handle_*_s *tz_handle_*` | 1 ポインタ値（`ref H` も二重ポインタではなく同じ 1 ポインタ） |

`i128`・`f16`・`f128`・10 進浮動小数点（`d32`〜`d128`）・文字型（`char` / `utf8char`）・通常の `union`・タプル・連結リスト・クロージャ関数値・戻り値の借用は公開 ABI に直接載せることはできません（`E1008`）。

## C ヘッダーとオブジェクトの生成・リンク

ライブラリとしてビルドする場合はエントリーポイント（`Main.tz` の実行式や `def main`）は不要です。

```tsuzuri run=42
export def add :: i64 -> i64 -> i64 = \left right ->
    left + right

add 20 22
```

以下のコマンドで C ヘッダーとネイティブオブジェクトを生成し、C ホストとリンクできます。

```sh
tsuzuri build Main.tz --emit header -o add.h
tsuzuri build Main.tz --emit object -o add.o
clang -O2 main.c add.o -o addhost
./addhost
```

生成される `add.h` は C99 / C11 / C++17 以降に対応しています。

```c
/* Generated by Tsuzuri. bool uses int32_t. Narrow integers use normalized 32-bit ABI values. */
#pragma once
#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

int64_t tz_add(int64_t arg0, int64_t arg1);

#ifdef __cplusplus
}
#endif
```

別々にビルドした複数の Tsuzuri ライブラリのヘッダーを 1 つの C / C++ ソースで並べて `#include` することも可能です。共通のバッファ記述子や `tsuzuri_trap_info` はバージョン付きガードマクロ `TSUZURI_COMMON_DECLARATIONS_1` で保護され、同名レコードやハンドルの `typedef` も構造体レイアウトの 64-bit ハッシュ値を持つガード（`TSUZURI_LAYOUT_<name>`）で保護されるため、同一型は重複定義にならず、異なる定義が衝突した場合はプリプロセッサの `#error` で即座に検出されます。

### 所有バッファの受け取りと `tsuzuri_free`

配列や文字列を所有値として返す `export def` は、第 1 引数の出力用構造体へポインタと長さを書き込みます。ホストは読み取り後に必ず `tsuzuri_free(buf.ptr)` を 1 回呼び出します（`tsuzuri_free(NULL)` は無操作として安全に無視されます）。

```c
#include <stdio.h>
#include "tag.h"

int main(void) {
    tsuzuri_ubyte_buffer tag;
    tz_make_tag(&tag, 3);
    fwrite(tag.ptr, 1, (size_t)tag.len, stdout);
    fputc('\n', stdout);
    tsuzuri_free(tag.ptr);
    return 0;
}
```

`string` は常に UTF-16 コード単位列（`uint16_t`）、`utf8string` は検証済み UTF-8 バイト列（`uint8_t`）です。`TSUZURI_STRINGS=compact` でビルドした場合でも公開 ABI は不変であり、内部で Latin-1 保持されている文字列はホスト境界で自動的に UTF-16 へ変換されます。

## ホスト関数・C 関数のインポート（`extern`）

### リンク名とシンボル集約

リンク名を省略した `extern def double_cents :: i64 -> i64` は、ネイティブでは `tsuzuri_host_<モジュール名>_double_cents` シンボルを参照し、`--emit header` にもホストが実装すべきプロトタイプが出力されます。既存の C ライブラリ関数を直接呼ぶ場合は、次のようにリンク名文字列を指定します（リンク名付き宣言はシステムヘッダー側にある前提のため `--emit header` には出力されません）。

```tsuzuri run=ok
extern "no_such_c_function" def unused_ext :: i64 -> i64

def helper :: i64 -> i64 = \x -> unused_ext x

"ok"
```

上記のとおり、ネイティブ実行ファイル（`--emit exe` / `run`）ではエントリーポイントから到達しない関数はコンパイル対象から外れるため、未使用の公開関数だけが参照する外部シンボルがリンクエラーを起こすことはありません。

また、Win32 の `SendMessageW` のように 1 つの C 関数を用途別の型で呼び分けたい場合、ネイティブターゲットでは下げた後の各引数・戻り値の低レベル ABI 分類（32-bit 整数、64-bit 整数またはポインタ、`f32`、`f64`、`void`）が一致していれば、同一リンク名に対して複数の別名 `extern def` を宣言できます。

### 不透明ハンドル（`extern type`）と NULL ニッチ表現

ホスト側リソースのポインタを Tsuzuri 内で型安全に扱うため、3 種類の不透明ハンドル宣言が用意されています。

| 宣言構文 | 満たす性質 | 用途と静的保証 |
| --- | --- | --- |
| `extern type Counter` | 非 Copy・`Send`（非 `Sync`） | `fopen` や独自オブジェクトなど、解放関数へムーブして 1 回だけ破棄すべき所有ハンドル |
| `extern type copy Hwnd` | `Copy`・`Capture`・`Send`・`Sync` | Win32 の `HWND` やストックオブジェクトなど、呼び出し側が所有権を持たない識別子ハンドル |
| `extern type local Hdc` | 非 Copy・非 `Capture`・非 `Send`・非 `Sync`（`pinned` 効果を誘導） | Win32 `HDC`、OpenGL コンテキスト、COM STA ポインタなど、取得した OS スレッド以外から触れてはならないスレッド拘束ハンドル |

Objective-C の物体（`id`）は、不透明ハンドルの代わりに `extern class` で宣言します。値が強い参照を所有し、drop で release されます（[Objective-C 連携](./objective-c.md)）。

`local` ハンドルを直接または間接に扱う関数にはコンパイラが自動的に `pinned` 効果を推論し、`tzroutine { ... }` や `Parallel.*` での別スレッド起動および一般クロージャへの格納を `E1013` で静的に禁止します（`Routine.with_locked_thread` や同期ロックヘルパー `Mutex.with_lock` 等には渡せます）。

ネイティブターゲットでは、非 `Maybe` の `H` および `ref H` は常に非 Null ポインタであることが境界で検査され、`NULL` が渡されると即座に `null extern handle` トラップとなります。`NULL` を取り得る引数や戻り値には **`Maybe<H>`・`Maybe<ref H>`・`Maybe<ref Record>`** を使用します。これらはタグを持たない 1 ポインタ（8 バイト、`None` = `NULL`、`Some` = 非 `NULL`）にゼロコストで表現されます。

### 可変参照（`ref mut`）・`@count`・`ZString`・静的コールバック

ネイティブの `extern def` ではさらに以下の C 連携機能を利用できます。

- **入出力引数（`ref mut`）**: スカラー・レコード・`copy` ハンドルの `ref mut` は一時領域へのコピーのポインタを渡して呼び出し後に書き戻します。可変スライス `ref mut [T]`（`i64`・`f64`・`ubyte`・`i16u`・`i32`・`i32u`）は排他借用のもとでゼロコピーの書き込みポインタと長さを渡します。
- **長さ引数の型指定（`@count`）**: `@count(1, i32u)` のように指定すると、1 始まりの引数番号のスライス・文字列バッファに付随する長さ引数を `i32`・`i32u`・`i64`・`i64u` に合わせるか、`none` で省略できます。
- **NUL 終端 UTF-16 文字列（`ZString`）**: `LPCWSTR`（`const uint16_t *`）を要求する API には `ref ZString` または `Maybe<ref ZString>` を渡せます（リテラルからは `ZString.literal "text"` でヒープ確保なしに生成可能）。
- **静的コールバックと `FnPtr` / `Anchor`**: `extern` の引数にスカラー・ハンドルを入出力とする関数型を書くと、型パラメーターを持たないトップレベル関数を C 関数ポインタとして渡せます。関数ポインタ自体を構造体フィールド等で保持する場合は [`FnPtr.of`](../stdlib/memory/fnptr.md)、コールバック内から Tsuzuri 側の状態へ安全にアクセスする場合は [`Anchor`](../stdlib/memory/anchor.md) を使用します。`main` が終了した後にホストスレッドからコールバックが呼ばれた場合は未定義動作に陥らず即座にフェイルファストで停止します。

### C 構造体レイアウト（`@c_layout`）とメモリビュー（`extern view`）

通常のレコードは境界で 32-bit 正規化と独自詰め替えを行いますが、OS や C ライブラリの構造体（Rust の `#[repr(C)]` に相当）とバイト単位で一致させたいレコードには **`@c_layout`** または **`@c_layout(pack = N)`**（`N` は `1`・`2`・`4`・`8`・`16`）を付与します。

```tsuzuri run=30
@c_layout
record NativeRect { left: i32, top: i32, right: i32, bottom: i32 }

def width :: ref NativeRect -> i32 = \r ->
    r.right - r.left

let rect = NativeRect { left: 10, top: 0, right: 40, bottom: 20 }
width (ref rect)
```

- フィールドには固定幅数値型（`bool` は C の `_Bool` と Win32 `BOOL` の幅差による事故を防ぐため不可、`i8u` や `i32` を使用）、固定長数値配列 `[T; N]`、入れ子の `@c_layout` レコード、`extern type copy` ハンドル、`Maybe<Handle>`、`FnPtr<F>`、`ref ZString` / `Maybe<ref ZString>`（入力専用）を配置できます。生成される `.h` にはサイズと全フィールドオフセットを検証する `_Static_assert` が出力されます。
- ホストが所有する構造体アドレス（`i64`）を C ラッパーなしで直接読み書きしたい場合は、`extern view def read_rect :: i64 -> NativeRect` および `extern view def write_rect :: i64 -> ref NativeRect -> unit` を宣言します（NULL およびアライメント違反は実行時トラップで安全に検査され、パディングバイトは保護されます）。

#### 構造体の値渡しと値返し

`@c_layout` レコード `R` を `ref` なしで `extern def` の引数に書くと C の構造体の値渡し（C の `T`）、結果に書くと値返しになります。`ref R` は `const T *`、`ref mut R` は `T *` です。`@c_layout` のないレコードは、`ref` の有無によらず正規化した一時構造体へのポインターのままです。`export def` は `@c_layout` のレコードもポインターで受け渡します。静的コールバックと `FnPtr<F>` の引数と結果には、`ref` の有無によらずレコードを書けません（スカラーとハンドルだけです。書くと `E1008`）。

```tsuzuri
@c_layout
record Rect { left: i32, top: i32, right: i32, bottom: i32 }

@c_layout
record Point { x: i32, y: i32 }

// BOOL PtInRect(const RECT *lprc, POINT pt);
@trusted
extern "PtInRect" def pt_in_rect :: ref Rect -> Point -> i32
```

コンパイラはターゲットごとに C コンパイラ（Clang）と同じ分類を行います。

| ターゲット | 引数 | 結果 |
| --- | --- | --- |
| Windows x64（MSVC・MinGW） | 大きさが 1・2・4・8 バイトなら整数レジスター 1 つ（`{ f32, f32 }` も整数レジスター）。ほかは複写へのポインター | 同じ大きさなら整数レジスター。ほかは先頭の隠れた引数 |
| AArch64（Windows・Linux・macOS） | 同じ浮動小数点型のフィールド 1〜4 個からなる構造体（HFA）は浮動小数点レジスター。ほかは 16 バイト以下なら整数レジスター、それより大きければ複写へのポインター | HFA は浮動小数点レジスター。ほかは 16 バイト以下なら整数レジスター、大きければ呼び出し側が渡す領域 |
| System V x86-64（Linux） | 16 バイト以下で各フィールドが自然な整列にある構造体は、8 バイトごとの全部が残りのレジスターに収まるときに、8 バイトごとに整数レジスターか SSE レジスター。レジスターが足りない構造体は全体がスタックに回り（後ろのスカラーは残りのレジスターを使います）、ほか（`pack` でフィールドが整列から外れたものを含む）もスタック上の複写 | 同じ分類で `rax`・`rdx`・`xmm0`・`xmm1`。ほかは先頭の隠れた引数 |

- 引数は左から右へ評価され、メモリーで渡す構造体は呼び出しごと・引数ごとの新しい複写です。呼び出し先が書き換えても Tsuzuri の値は変わりません。
- `FnPtr` や `ref ZString` のフィールドを持つ `@c_layout` レコードは入力専用で、結果にすると `E1008` です。
- WebAssembly で到達した値渡しは `E1008`（`abi_native_only`）です（`ref R` は WebAssembly でも使えます）。x86-64 と AArch64 以外のターゲットは `E1008`（`abi_record_by_value_target`）です。`tsuzuri check` はターゲットを知らないので受け付け、誤りは `build` で報告されます。
- リンク名のない `extern def` の C ヘッダーのプロトタイプは、値渡しを `tz_record_… f(tz_record_… arg0)` の形で出力します。
- 高速バックエンド（`--backend fast`）は、そのターゲットでスカラー 1 つ（整数か浮動小数点数）に下がる構造体だけを値で受け渡します。表のほかの形（複数のレジスター、HFA、ポインター、隠れた引数）になる構造体は `E2002` で、既定の `--backend llvm` でビルドします。
- 宣言が C 側の構造体と一致することは、ほかの `extern` と同じく宣言を書く人の責任です。可変長引数の関数と、16 バイト以上の整列を持つ構造体は扱いません。
- **互換性**: 以前の版は `ref` のない `@c_layout` レコードも `const T *`（結果は先頭の out 引数）で受け渡していました。ポインターを取る C の関数の宣言は、引数を `ref R` に、out 引数を `ref mut R` に書き直します（[安定性と互換性ポリシー](./stability.md#c-abi-の既知の変更)）。

### `@trusted` とリンク入力

コンパイラは外部 C 関数の内部実装までは検証できないため、人間が ABI と所有権契約を確認した `extern` 宣言には `@trusted`（必要に応じて `@trusted pure no_alloc no_trap terminates`）を付与します。未付与の `extern` 使用は `--warn untrusted-extern` および `tsuzuri audit` で `W1010` として報告され、マニフェストで `[capabilities]` を有効化したプロジェクトでは `ffi` 権限が要求されます。

また、Tsuzuri 実行ファイルに外部のオブジェクトやライブラリをリンクする場合は、`Tsuzuri.toml` の `[native]` セクション（`link`・`libraries`・`search`）または CLI の `--link PATH`・`-l NAME`・`-L DIR` を使用します。

## `tsuzuri bindgen` による C ヘッダーからの自動生成

`tsuzuri bindgen` は Clang（`TSUZURI_CLANG`）で C ヘッダーの AST とマクロ定義を解析し、ABI の一致が静的に保証される宣言のみを `.tz` モジュールへ出力します（64-bit Linux および macOS Apple Silicon 対応）。

```sh
tsuzuri bindgen sample.h -o Sample.tz \
  --include-dir vendor \
  --buffer sample_sum:values:count \
  --consume counter_free:counter \
  --nonnull counter_free:counter
```

- **生成対象**: 外部リンケージを持つ非可変長引数関数（`extern "symbol" def`）、`i32` に収まる `enum` 定数および整数リテラル `#define` マクロ（`const`）、32/64-bit スカラーフィールドのみを持つタグ付き `struct`（`record`）、不完全型 `struct tag;` のポインタ（`extern type`）、対応型の `typedef`（`type`）、およびスカラー・ハンドル入出力の関数ポインタ引数です。C の `_Bool` 戻り値・コールバック引数は上位ビット未定義を避けるため `i8u` として受け取ります。
- **安全な Null 既定**: C のポインタは `NULL` になり得るため、`_Nonnull` や `nonnull` 属性または `--nonnull` 指定がないハンドル・`const struct *` はすべて `Maybe<...>` として生成されます。
- **上書き保護と `@trusted`**: 出力ファイル先頭には `// Generated by tsuzuri bindgen. Do not edit.` が記録され、このマーカーを持たない手書きファイルへの上書きは `E2003` で拒否されます。また、ABI 一致だけでは関数の意味上の安全性までは保証されないため、`bindgen` は `@trusted` を自動付与しません。

生成されたモジュールを別モジュールから呼び出す構成例は次のとおりです。

```tsuzuri project=bindgen file=Sample.tz
// Generated by tsuzuri bindgen. Do not edit.
const SAMPLE_LIMIT: i32 = 42
record SamplePoint { x: f64, y: f64, tag: i32 }
extern "sample_norm" def sample_norm :: ref SamplePoint -> f64
```

```tsuzuri project=bindgen file=Main.tz
export def check_limit :: i32 = Sample.SAMPLE_LIMIT

export def point_norm :: f64 -> f64 -> f64 = \x y ->
    let pt = Sample.SamplePoint { x: x, y: y, tag: 0 }
    Sample.sample_norm (ref pt)
```

## 共有ライブラリ（`--emit shared`）と各言語バインディング

macOS（`.dylib`）および Linux（`.so`）向けに公開 C ABI シンボルのみをエクスポートする共有ライブラリを生成し、同じソースから C#・Python・C++20 の型付きラッパーを生成できます。

```sh
tsuzuri build quote --emit shared --trap-mode return -o libquote.dylib
tsuzuri build quote --emit bindings-py --trap-mode return -o quote.py
tsuzuri build quote --emit bindings-cs --trap-mode return -o quote.cs
tsuzuri build quote --emit header --trap-mode return -o quote.h
tsuzuri build quote --emit bindings-cpp --trap-mode return -o quote.hpp
```

| 出力種別 | 対象言語・要件 | 特徴とメモリ・トラップ管理 |
| --- | --- | --- |
| `bindings-cs` | C#（.NET 8 以降、`AllowUnsafeBlocks`） | `[LibraryImport]` と `ReadOnlySpan<T>` によるゼロコピー入力、所有結果は `SafeHandle` 派生クラス（`OwnedBuffer<T>`・`OwnedString`）で自動 `tsuzuri_free` |
| `bindings-py` | Python 3（標準 `ctypes`） | 整数範囲と UTF-8 妥当性を事前検査し、所有結果は `str` / `bytes` / `array.array` へ複製して即座に `tsuzuri_free` |
| `bindings-cpp` | C++20（生成した `.h` を併用） | `tsuzuri::<name>` 名前空間の `inline` 関数、`std::span` / `std::u16string_view` / `std::string_view` 入力、ムーブ専用 RAII バッファ（デストラクタで自動 `tsuzuri_free`） |

ライブラリとバインディングの双方に `--trap-mode return` を付与すると、`tsuzuri_try_<name>` が使用され、Tsuzuri 内のゼロ除算や境界外アクセスでホストプロセス全体が終了する代わりに各言語の例外（`TsuzuriTrapException` / `TsuzuriTrap` / `tsuzuri::<name>::trap_error`）へ安全に変換されます。

## 言語間 ThinLTO（`--emit bitcode`）

`--emit object` では小さな公開関数も関数呼び出し境界として残りますが、`--emit bitcode` を使うとプログラム本体と必要な C ランタイムを単一の ThinLTO LLVM ビットコード（`.bc`）へ統合して出力できます（Windows と `wasm64` を除くネイティブおよび `wasm32` に対応。C ランタイムを含むネイティブプログラムでは `llvm-link` が必要です）。

```sh
tsuzuri build Main.tz --emit bitcode -o add.bc
clang -O3 -flto=thin host.c add.bc -o host
```

ビットコードを生成した `TSUZURI_CLANG` と同一バージョンの Clang を用いてホスト側も `-flto=thin`（Linux では `-fuse-ld=lld` も併用）でコンパイル・リンクすることで、`tz_add` のような関数が C / C++ ホストのホットループ内に直接インライン展開されます。

## ホスト提供アロケータとスレッド境界の規約

- **`--allocator host`**: ヒープ確保をホスト定義の `void *tsuzuri_host_alloc(uint64_t size, uint64_t align)`・`tsuzuri_host_free`・`tsuzuri_host_realloc`（`align` は常に `16`、先頭 16 バイトは内部サイズヘッダー）へ委譲します。複数の tzroutine や `Parallel.*` スレッドから同時に呼ばれ得るため、ホスト側でスレッドセーフに実装し、ホストへ返った所有バッファの解放には引き続き `tsuzuri_free` を使用してください。
- **イベントループとブロッキング呼び出し**: `export def` の呼び出しは内部で起動したすべての tzroutine が完了するまでホストへ戻りません。GUI の UI スレッドやイベントループをブロックしたくない場合は、ホスト側のワーカースレッドから `tz_*` を呼び出します。また、tzroutine 内から `extern` を呼ぶとスケジューラは自動的に論理プロセッサ `P` を他スレッドへ譲渡可能にし、コールバックで再入した際は元の OS スレッド上で継続します。
- **報告の出力先**: `--emit object` や `--emit shared` の出力を組み込んだホストでは、tzroutine ランタイムなどの報告はホストの標準エラーへ書かれ、標準エラーの行き先はホストが決めます。macOS の実行ファイルが行う unified logging への送信（[Finder から起動したアプリの報告](./debugging.md#finder-から起動したアプリの報告)）は、object と共有ライブラリでは行いません。
