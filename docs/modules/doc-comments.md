# ドキュメントコメントと doctest

`///` で始まる行コメントは、直後の宣言に対する**ドキュメントコメント**として解析されます。ドキュメントコメントは Markdown で記述でき、`tsuzuri doc` による API リファレンス生成、言語サーバー（`tsuzuri lsp`）のホバー表示、`@deprecated` による非推奨警告、構造化タグによる計算量メタデータ管理、および `tsuzuri test --doc` によるコード例の自動検証（doctest）に活用されます。

## 要点

- 宣言の直前に連続して置かれた `///` 行が Markdown ドキュメントコメントとなり、先頭の空白1文字が自動除去されて改行で結合される。
- `///` を付与できるのはトップレベルの型・関数・定数・型クラス宣言および型クラス内メソッド `def` のみであり、実装側の `fn` / `let` や `instance`・ローカル変数・フィールドに置くと構文エラー `E0002` となる。
- `@complexity`・`@since`・`@see`・`@deprecated` の構造化タグに対応し、`@deprecated` が付いた宣言を他パッケージ（または `std`）から参照すると警告 `W1005` が報告される。
- コメント内の ```` ```tsuzuri ```` コードブロックは `tsuzuri test --doc` によって型検査・実行・テスト・エラーコード照合が行われ、ドキュメントと実装の乖離を防ぐ。
- `tsuzuri doc <input> -o <outdir>` は公開宣言のみの Markdown リファレンスを生成し、`.tsuzuri-docs` マーカーファイルで既存ディレクトリの誤上書きを防止する（`E2003`）。

## 配置規則と誤配置エラー（`E0002`）

### 基本構文と整形規則

`///` の直後にある半角スペース1文字（存在する場合）がトリミングされ、残りのテキストがそのまま Markdown として保持されます（`////` のように4文字続けた場合は本文が `/` で始まります）。通常の `//` 行コメントや `/* ... */` ブロックコメントはドキュメントには含まれません。

| 配置対象 | 可否 | 備考・違反時の挙動 |
| --- | --- | --- |
| `def`（`pure` / `const` / `@literal` / `export` / `extern` / `private` 含む） | 可 | シグネチャ宣言の直前に記述する（`private` 宣言のコメントは LSP ホバーでは見えるが `tsuzuri doc` 出力からは除外される） |
| `record` / `union` / `type` / `const` | 可 | 各宣言の直前に記述する |
| `class` および型クラス内のメソッド `def` | 可 | 型クラス全体と各メソッドの双方に記述可能 |
| 実装側の `fn` / `and` / `let` | **不可（`E0002`）** | 必ず先行する `def` シグネチャ側に記述する |
| `instance` 宣言およびそのメソッド | **不可（`E0002`）** | インスタンス実装には付与できない |
| レコードのフィールド、共用体のケース | **不可（`E0002`）** | 型宣言全体の `///` 内で説明する |
| 関数内のローカル `let`、`test` / `bench`、ファイル末尾 | **不可（`E0002`）** | 後続に有効な対象宣言がない孤立 `///` も構文エラーとなる |

他言語のように誤配置されたドキュメントコメントを黙って無視するのではなく、構文エラー `E0002` として即座に検出するため、`fn` 側に書いて公開ドキュメントから抜け落ちるミスを防げます。

## 構造化タグ（`@complexity`・`@since`・`@see`・`@deprecated`）

`///` 本文の行頭（先頭空白を除く）が特定のタグ名で始まり、直後が空白または行末である行は構造化タグとして扱われます。本文の段落やコード例との間には空の `///` 行を1行挟みます。

```tsuzuri project=doc-tags file=Stats.tz
/// 配列の全要素の総和を返します。
///
/// @complexity O(n)
/// @since 0.1.0
/// @see Array.sum
def total :: [i64] -> i64 = \xs ->
    Array.sum xs

/// @deprecated Stats.total を使用してください
def legacy_total :: [i64] -> i64 = \xs ->
    total xs
```

```tsuzuri project=doc-tags file=Main.tz run=15
Stats.total [1, 2, 3, 4, 5]
```

### 各タグの仕様

| タグ | 行数 | 値の形式と役割 |
| --- | --- | --- |
| `@complexity` | 最初の1行 | 時間計算量。`O(式)`、または `amortized O(式)` / `expected O(式)`（必要に応じて `, worst O(式)` を併記）。式には `1`、入力サイズ `n`・`m`・出力サイズ `k`、`log`・`log^2`、`+`・`*` を使用（例: `O(n log n)`、`expected O(1), worst O(n)`）。標準コレクションのリファレンス表はこのタグから自動生成される |
| `@since` | 最初の1行 | その公開 API が導入されたバージョン番号（例: `0.1.0`） |
| `@see` | 複数行可 | 関連するモジュール名または `Module.name`（1行に1項目） |
| `@deprecated` | 最初の1行 | 宣言を非推奨としてマークし、後ろに続くテキストを移行案内メッセージとする |

### `@deprecated` と非推奨警告 `W1005`

`def`（`extern def` を除く）・`record`・`union` に `@deprecated` タグを付与すると、**別パッケージ（または標準ライブラリ `std`）** からその関数・型・共用体コンストラクタを参照した箇所に対して警告 `W1005` が出力されます。

```text
warning[W1005]: 'LegacyPkg::Stats.legacy_total' is deprecated: Stats.total を使用してください
```

- **同一パッケージ内の抑制**: 非推奨宣言を定義しているパッケージ自身の内部から呼び出した場合は `W1005` は発生しません。これにより、移行期間中にパッケージ作者自身の `--deny-warnings` ビルドを壊さずに段階的な廃止を進められます。
- **コード生成への非干渉**: `@deprecated` や他の構造化タグは生成されるバイナリや実行性能には一切影響しません。

## コード例と `tsuzuri test --doc`（doctest）

公開宣言（`private` 以外の対象宣言）の `///` コメント内に記述した ```` ```tsuzuri ```` コードフェンスは、単なる説明文ではなく実行可能なテストケース（doctest）になります。

### コードフェンスの検証モードと隠し行

開きフェンスの `tsuzuri` の後ろに、検証方法を指定するオプションを1つ記述できます（コメント本文のカラム1から書き始めます。インデントされたフェンスや不正なオプションは `E2011` で報告されます）。

| フェンス指定 | `tsuzuri test --doc` の検証内容 | `tsuzuri doc` / LSP ホバーでの表示 |
| --- | --- | --- |
| ```` ```tsuzuri ````（無印） | 型検査（`check`）が成功することを確認（実行はしない。ファイル・通信・乱数等の例に適する） | そのまま表示 |
| ```` ```tsuzuri run=<期待出力> ```` | 型検査後、ネイティブ実行した標準出力がパーセント符号化された `<期待出力>` と一致することを確認 | フェンス直後に `Output:` ブロックを自動付加して表示 |
| ```` ```tsuzuri test ```` | コード内の1つ以上の `test "..." = ...` を実行して全件成功することを確認 | `tsuzuri` フェンスとして表示 |
| ```` ```tsuzuri fails=<エラーコード> ```` | 型検査が失敗し、最初の診断コードが `<エラーコード>`（例: `E1012`）と一致することを確認 | フェンス直後に ``Compile error: `E1012`.`` を自動付加して表示 |
| ```` ```tsuzuri ignore ```` | 型検査・実行をスキップする（`--list` には表示される。意図的にトラップする例や外部環境依存の例に使用） | `tsuzuri` フェンスとして表示 |

- **`run=` のパーセント符号化**: 空白は `%20`、改行は `%0A`、`%` 自身は `%25`、バッククォートは `%60` として UTF-8 パーセント符号化で記述します（`run=` のように空にした場合は出力が空であることを検証します）。
- **`# ` による隠し行**: コード例の中で `#` 単独または `# `（シャープ + 半角空白1文字）で始まる行は、doctest のコンパイル・実行時には先頭の `# ` が外されて評価される一方、`tsuzuri doc` やエディタのホバー表示からは自動的に隠されます。読者に見せる必要のない前準備コードの記述に便利です。
- **トラップを伴う例の扱い**: doctest 実行中の未捕捉トラップは `E2005` によるテスト失敗となります。純粋計算のトラップ動作自体を検証したい場合は [`Domain.run`](../stdlib/core/domain.md) で包んで `test` または `run=` で検証し、プロセスを終了させるトラップ例を掲載する場合は `ignore` を指定します。

```tsuzuri project=doctest-demo file=MathUtil.tz
/// 非負整数の範囲内で値をクランプします。
///
/// ```tsuzuri run=10
/// # let upper = 10
/// MathUtil.clamp 0 upper 25
/// ```
///
/// ```tsuzuri test
/// test "clamp keeps in-range value" =
///     Test.equal (ref (MathUtil.clamp 0 10 7)) (ref 7)
/// ```
///
/// ```tsuzuri fails=E1003
/// MathUtil.clamp 0 10 "invalid"
/// ```
def clamp :: i64 -> i64 -> i64 -> i64 = \lo hi x ->
    if x < lo then lo elif x > hi then hi else x
```

```tsuzuri project=doctest-demo file=Main.tz run=7
MathUtil.clamp 0 10 7
```

### `tsuzuri test --doc` の実行と留意点

```sh
# カレントパッケージの全 doctest を実行
tsuzuri test --doc .

# 特定のモジュール・関数名で絞り込み、警告もエラーとして扱う
tsuzuri test --doc . --filter MathUtil.clamp --deny-warnings
```

- 各コード例はルートパッケージの `Main.tz` を一時的に置き換えた独立プログラムとして検査・実行されます。そのため **`Main.tz` 自身の宣言に書かれたコード例は実行対象外**（`ignored` 計上、警告 `W2001`）となります。doctest を付与したい公開関数・型は `Main.tz` 以外のモジュールに配置します。
- 1件でも doctest が失敗すると `E2006` が出力され、終了コード `1` となります。パッケージあたりの doctest 上限は 10,000 件です（超過は `E1017`）。

## `tsuzuri doc` によるリファレンス生成

`tsuzuri doc` コマンドは、パッケージ（または `std`）の型検査を実行したうえで、公開（public）宣言のみを抽出した Markdown API リファレンスを出力します。

```sh
tsuzuri doc . -o docs/api
```

- **出力構成**: モジュール一覧の目次 `index.md` と、各モジュールのページ（例: `Geometry::Point` なら `Geometry.Point.md`）が生成されます。`private` 宣言、`instance` 実装、`const` の初期化式本体は出力されません。
- **`.tsuzuri-docs` マーカーによる上書き保護（`E2003`）**: 出力先ディレクトリが新規であれば自動作成し、内部に `generated by tsuzuri doc` を含む `.tsuzuri-docs` マーカーファイルを配置します。既存のディレクトリを指定した場合、このマーカーファイルが存在しないディレクトリや `.tz` / `.tt` / `.tc` ソースを含むディレクトリ、シンボリックリンク先に対しては誤消去を防ぐため `E2003` で書き込みを拒否します。マーカーがあるディレクトリは生成時に丸ごと置換されるため、手書きのファイルを混在させないでください。
- **モジュール名の衝突注意**: `Index.tz` という公開モジュールが存在すると `index.md` とファイル名が衝突するため `E2003` となります。
